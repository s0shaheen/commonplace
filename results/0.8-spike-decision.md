## Decision

✅ **ALL THREE GATES PASS → PROCEED to Phase 1.**

0.2 and 0.3 cleared empirically on the founder's real account. 0.4 was unblocked by founder decision on 2026-05-27: rather than run the 5-person comparison study, the founder committed to the enriched-export thesis directly and declared **visual analysis + entity extraction** in-scope for v1. The remaining design freedom is *how* enrichment runs and *how* the output is presented to be usable — addressed in the Phase 1 enrichment design spec, not gated further.

## Surprises that reshape the Phase 1 architecture

1. **No server is technically required.** Capture, text+subtitle enrichment, video (.mp4) download, *and* visual enrichment all run fully client-side with a BYO Gemini key. The Cloudflare Worker proxy drops from "required" (spec §5) to an **optional hosted-credits convenience tier** — a business choice, deferred.
2. **Video .mp4 export is a new first-class, AI-independent feature.** Mirroring the page's own video request (credentialed CORS + `Range` + DNR-injected `Referer`, no ACAO injection) downloads any creator's video. Ships in the Pro export engine regardless of AI.
3. **Auto-scroll trips a ~360-item soft throttle** (3 runs all stopped at 359); human-paced scrolling does not. The Phase 1 scraper must pace like a human and/or offer a manual-assist "you scroll, we capture" mode. Not a feasibility blocker.
4. **Visual enrichment is slow/$$ at library scale** → it must be selective/opt-in, never auto-on-all. This is the central constraint shaping the enrichment design.

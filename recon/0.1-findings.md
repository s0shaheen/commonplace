# 0.1 DevTools Recon — TikTok Favorites

- Endpoint path: `https://www.tiktok.com/api/user/collect/item_list/`
- Method: GET
- Key query params: `secUid`, `cursor`, `count`, `coverFormat`, `needPinnedItemIds`, `post_item_list_request_type`, `msToken`, `X-Bogus`, `X-Gnarly`, plus standard browser/device params (`aid`, `device_id`, `os`, `browser_*`, etc.)
- Signed per scroll? : **YES** — `msToken` / `X-Bogus` / `X-Gnarly` present; `cursor` changes on each request. (We never generate these — the page does; we skim the responses.)
- Item array path in response: `itemList`
- Cursor / hasMore: not present in the copied subtree (only `itemList` was copied); cursor confirmed changing per request. **Irrelevant to our approach** — we passively intercept the page's own requests, we don't paginate ourselves.
- `id` type: **string** (e.g. `"7578265440993199126"`) → safe from JS number-precision loss.
- Per-item fields confirmed: `id`, `desc`, `createTime`, `author.uniqueId`, `author.nickname`, `video.playAddr`, `video.downloadAddr`, `video.cover`, `video.originCover`, `video.duration`, `video.subtitleInfos[]` (free transcript source!), `music.{title,authorName}`, `challenges[].title` (hashtags), `stats.{playCount,diggCount,commentCount,shareCount,collectCount}`, `imagePost` (present only for slideshows).
- Video URL fetchable from extension? : **NO — 403 / CORS-blocked.** TikTok's CDN refuses cross-origin byte reads, so full-video bytes cannot be read by any client-side code. Confirmed in the live 0.3 run. → Full-video/visual enrichment requires a **server-side proxy** (deferred decision). v1 local enrichment pivoted to **text-only** (caption + hashtags + subtitles).
- Capture run (0.2, first pass): 1316 captured / 1463 visible (~90%). Caveats: (a) auto-scroll stopped early (fixed: now count-stability based), (b) `chrome.storage` 10MB quota exceeded by storing `raw` (fixed: dropped `raw` + added `unlimitedStorage`), (c) historical ~14% favorites deletion rate (Exp 01) means true ceiling may be ~1316.
- **Final (0.2): manual scroll → 1313 captured of 1463 listed → 🟢 PASS** (the ~150 gap is deleted favorites, unservable to anyone). Passive interception is complete. **Caveat → Phase 1:** automated fast scroll deterministically trips a ~360-item soft throttle (3 runs all stopped at 359); human-paced scrolling does not. Scraper must pace scrolling like a human and/or offer a manual-assist "scroll yourself, we capture" mode.
- **Final (0.3): 19/20 valid enriched JSON → 🟢 PASS.** Subtitle files ARE fetchable and Gemini is callable from the browser → text+subtitle enrichment is fully local/BYO-key, no proxy.
- **Final (download/visual): 🟢 PASS — overturns "video needs a proxy".** Naive `fetch` 403s, but mirroring the page's request (credentialed CORS `credentials:"include"` + `Range: bytes=0-` + DNR-injected `Referer: https://www.tiktok.com/`, and NOT injecting ACAO) downloads **any** creator's video client-side (proven). So: (a) **video .mp4 export works fully client-side, no proxy, AI-independent**; (b) **visual enrichment can run locally too** (read bytes → Gemini BYO-key; inline ≤~18MB, File API for larger). Path 1 (`chrome.downloads`) only works for owner videos (can't send cookie/Range) — Path 2 (fetch→blob) is the mechanism.

## Structured extraction / NER eval

*confidence: high*

### Verdict
The gold standard is a fixed order of operations: (1) freeze an annotation TARGET (closed type vocabulary + written guidelines defining what counts as an entity, its granularity, and canonical form) and validate it with inter-annotator agreement rounds; (2) build a stratified, double-annotated, adjudicated gold set split into dev and a frozen TEST; (3) score with the MUC-5/SemEval-2013 Task 9.1 family of matching schemes (strict/exact/partial/type via nervaluate, adapted to span-free generative output with normalized+fuzzy mention matching and Hungarian bipartite alignment), reporting micro AND macro P/R/F1 per type; (4) evaluate grounding as a separate stage with entity-linking metrics (InKB micro-F1, NIL-aware modes a la ELEVANT/TAC-KBP, disambiguation accuracy given gold mention); (5) only then compare two pipelines — on the same frozen test set, with paired bootstrap resampling (10k resamples, 95% CI on ΔF1) and per-stratum breakdowns. Inter-run agreement between two unvalidated pipelines measures prompt-output stability, not quality — two systems can agree on wrong answers, and exact-string+exact-type matching mechanically inflates disagreement because most benign variation (casing, articles, boundary choices, near-synonym types) is scored as total error; MUC and SemEval created the partial/type schemes precisely to separate that variation from real mistakes. The experiment just run (ad-hoc prompt, ad-hoc ontology, exact-string match, no ground truth, agreement-as-verdict) violates steps 1-5 simultaneously and its number is uninterpretable; the fix is not a better prompt but building the measurement instrument first.

### Method
STEP 0 — Define the annotation target before touching any pipeline. Write annotation guidelines in the ACE/OntoNotes tradition: a CLOSED entity-type vocabulary (7-12 types: song, place, film, product, book, person...), a definition of what counts as a mention (named/specific only vs nominal; ACE tags maximal extent + head, and distinguishes specific vs generic mentions — you likely want specific, groundable entities only), granularity rules (is "the pasta place in Brooklyn" an entity? is a song heard-but-not-named one?), and the unit of annotation. For video with no character offsets, the correct unit is the video-level typed entity SET: gold item = (video_id, canonical surface form + accepted aliases, type, external ID or NIL). Handle nesting/specificity with explicit rules (e.g., annotate both "Joe's Pizza" PLACE and "Brooklyn" LOC, or only the most specific groundable entity — decide once, in writing).

STEP 1 — Validate the instrument with IAA. Pilot: 2 annotators independently annotate 30-50 videos; measure entity-level agreement F1 (treat annotator A as gold, B as prediction, under your matching scheme) and Cohen's kappa on type-given-matched-mention. Refine guidelines in rounds (published NER corpora like KIND/HistNERo used ~5 rounds of ~20 docs) until agreement plateaus. The final IAA is your human ceiling — publish it; system F1 above IAA is meaningless.

STEP 2 — Build the gold set. Stratified random sample from the 4,661-video corpus on the axes that plausibly drive performance: VTT present (53%) vs absent, slideshow (17%) vs video, duration, content domain. Size by power analysis (Card et al. 2020, EMNLP; their NLP-power-analysis notebooks): to detect a 3-5 point F1 difference at ~80% power you need on the order of 1,000+ gold entity mentions — at ~3-4 entities/video that is roughly 300 test videos + 100-150 dev videos. Double-annotate the test portion, adjudicate disagreements to produce the gold, then FREEZE test. All prompt/ontology/pipeline iteration happens on dev only; test is scored once per headline claim (TAC-KBP ran ~2,000 EL queries per year as reference scale).

STEP 3 — Implement the matching scheme. Base: SemEval-2013 Task 9.1 / MUC-5 five categories (COR, INC, PAR, MIS, SPU) and four schemes — strict (span+type), exact (span only), partial (overlap, 0.5 credit: P=(COR+0.5·PAR)/ACT, R=(COR+0.5·PAR)/POS), type (type correct + any overlap) — as implemented in nervaluate. Adapt to span-free generative output: mention match = Unicode-normalized, casefolded, article/punctuation-stripped string equality against gold surface+aliases (the "exact" analog), plus a fuzzy tier (rapidfuzz token-set ratio or Jaro-Winkler above a fixed threshold) as the "partial" analog — clinical LLM-NER work shows the exact-vs-fuzzy gap is ~7 F1 points, which is exactly the disagreement your exact-string matching inflated. Use Hungarian bipartite matching between predicted and gold entity sets per video so each gold entity pairs with at most one prediction (FAIRmat extract-eval / Databricks pattern: classify every field as match, mismatch, omission, or hallucination). Type is scored separately (type accuracy / kappa given matched mention); with a type hierarchy, give parent-match partial credit or report coarse and fine levels separately (cf. Twitter-FMNERG's 8 coarse / 51 fine types). Enforce the closed vocabulary at generation time with JSON-schema-constrained decoding so type strings are never free text — but remember structural validity is not correctness: 2026 benchmarking shows models pass schema/type checks at 96%+ while value accuracy sits at 0.69-0.83.

STEP 4 — Metrics. Report micro P/R/F1 (headline; entity-frequency weighted) AND macro-over-types (exposes rare-type collapse), plus a mandatory per-type table, under all four schemes; designate strict (normalized mention + type) as the headline number in advance. Evaluate grounding as a SEPARATE stage with entity-linking metrics: disambiguation accuracy given gold mention (isolates the resolver from extraction errors — ELEVANT's recognition-vs-disambiguation decomposition), end-to-end InKB micro-F1, and NIL as a first-class prediction with its own precision/recall (ELEVANT's four modes: all / InKB-only / unknown-only; TAC-KBP uses B³+ F1 so systems that never say NIL are penalized). If you publish confidence scores, add calibration (ECE/reliability diagram).

STEP 5 — Only now compare two pipelines. Run both ingestion variants (native-video vs keyframes+VTT) on the SAME frozen test set, 3 runs each to capture decoding variance (report mean±sd). Significance: paired bootstrap resampling over test videos, B=10,000, report ΔF1 with 95% CI and p<0.05 (Berg-Kirkpatrick et al. 2012; Dror et al. 2018 "hitchhiker's guide" is the standard NLP protocol). Break out results per stratum (VTT/no-VTT, slideshow) — the pipelines will differ most where their inputs differ. Pre-register the headline metric and the minimum ΔF1 that would change the design decision before looking.

STEP 6 — LLM-as-judge only for the residue. Use an LLM judge ONLY for mention-equivalence cases deterministic matching can't settle (paraphrases: "that pizza spot Joe's" ≡ "Joe's Pizza"), never for grounding correctness (that is deterministic ID equality). Validate the judge: ~200 dual-labeled examples, require Cohen's kappa ≥ 0.6 (≥ 0.8 strong) against human labels, keep a held-out adversarial slice, re-sample ~50 fresh cases periodically for drift. Wire the whole harness into CI with promptfoo (is-json + javascript assertions, side-by-side model matrix) or DeepEval (pytest-style metric gates) so every prompt change re-scores dev automatically.

### Evidence

- SemEval-2013 Task 9.1 defines four NER evaluation schemes (strict, exact-boundary, partial-boundary, type) built on the MUC-5 error categories COR/INC/PAR/MIS/SPU, with partial matches given 0.5 credit: P=(COR+0.5·PAR)/ACT, R=(COR+0.5·PAR)/POS; nervaluate is the maintained Python implementation — *https://github.com/MantisAI/nervaluate and https://www.davidsbatista.net/blog/2018/05/09/Named_Entity_Evaluation/*
- Naive token-level or exact-only matching misleads because boundary and surface-form variation is scored as total error even when the entity is essentially right; the MUC/SemEval schemes exist to separate this from real mistakes — *https://www.davidsbatista.net/blog/2018/05/09/Named_Entity_Evaluation/ (MUC-5 rationale); scheme definitions at https://pypi.org/project/nervaluate/*
- For generative LLM NER without character offsets, practice is to report exact-normalized AND fuzzy string matching; the gap is material (GLiNER fine-tuned: 68.98 micro-F1 exact vs 75.64 fuzzy on clinical notes) — *https://pmc.ncbi.nlm.nih.gov/articles/PMC11804004/ (Comparative analysis of generative LLMs for labeling entities in clinical notes)*
- Field-level LLM extraction eval classifies every output as match/mismatch/omission/hallucination with per-field P/R/F1, and uses Hungarian bipartite matching for arrays where order differs — *https://github.com/FAIRmat-NFDI/extract-eval and https://community.databricks.com/t5/technical-blog/end-to-end-structured-extraction-with-llm-part-1-batch-entity/ba-p/98396*
- Schema-validity metrics mask content errors: 16 of 21 models scored ≥96% on path recall/structure/type safety while value accuracy fell to 0.69-0.83 and perfect-response rate to 0.38-0.53 — so JSON-schema compliance alone proves nothing about extraction quality — *https://arxiv.org/html/2604.25359v1 (The Structured Output Benchmark, 2026)*
- ACE entity guidelines are the canonical prior art for defining the annotation target: closed type inventory, maximal-extent + head marking, nested mentions annotated, and mention classes (specific vs generic vs attributive) that decide what is annotatable at all — *https://www.ldc.upenn.edu/collaborations/past-projects/ace/annotation-tasks-and-specifications*
- Gold-set construction practice: guidelines refined over ~5 rounds of ~20 double-annotated docs, agreement measured with entity-level F1 and Cohen's kappa; IAA is the published human ceiling — *https://arxiv.org/pdf/2112.15099 (KIND corpus), https://arxiv.org/pdf/2405.00155 (HistNERo), https://arxiv.org/html/2603.06865 (Counting on Consensus, 2026)*
- Statistical power is routinely ignored in NLP; small test sets cannot detect small F1 differences — e.g., 2,000-item MT test sets have only ~75% power for a 1-BLEU difference; Card et al. provide notebooks to size test sets for a target minimum detectable effect — *https://aclanthology.org/2020.emnlp-main.745/ and https://github.com/dallascard/NLP-power-analysis (Card et al. 2020, With Little Power Comes Great Responsibility)*
- Paired bootstrap resampling (typically 10k resamples on paired per-item predictions, 95% CI on ΔF1, p<0.05) is the standard significance test for comparing two NLP systems on one test set — *http://nlp.cs.berkeley.edu/pubs/BergKirkpatrick-Burkett-Klein_2012_Significance_paper.pdf and Dror et al. 2018 via https://bricksdont.github.io/posts/2020/12/statistical-significance-testing/*
- Entity-linking (grounding) has its own metric standard: InKB micro-F1 with exact gold-ID match, GERBIL for standardized cross-system comparison, ELEVANT with four NIL-handling evaluation modes plus recognition-vs-disambiguation decomposition, and TAC-KBP's B³+ F1 which penalizes systems that never predict NIL — *https://github.com/ad-freiburg/elevant, https://arxiv.org/pdf/2208.07193 (ELEVANT), https://catalog.ldc.upenn.edu/LDC2018T16 (TAC KBP EL 2009-2013), https://dl.acm.org/doi/10.1145/3795134 (Entity Linking with Wikidata survey, ACM CSUR)*
- 2026 LLM-as-judge practice: calibrate on ~200 dual-labeled examples, require Cohen's kappa ≥0.6 (≥0.8 strong) vs human labels, keep an adversarial held-out slice, re-sample ~50 fresh examples periodically for drift; large-scale 2026 evaluation shows judges have high test-retest reliability yet severe biases, so kappa validation is mandatory — *https://futureagi.com/blog/llm-as-judge-best-practices-2026 and https://arxiv.org/pdf/2606.19544 (Reliability without Validity, 2026)*
- Nearest multimodal prior art is Grounded Multimodal NER (Twitter-GMNER, Twitter-FMNERG with 8 coarse/51 fine types), which evaluates entity-type pairs and entity-grounding pairs as separate subtasks — the same extraction-vs-grounding decomposition recommended here — *https://arxiv.org/html/2402.09989v4 and https://arxiv.org/html/2604.17319v1 (E2E-GMNER, 2026)*
- promptfoo provides is-json (JSON-schema validation) plus javascript/python assertions for field-level checks and side-by-side multi-model comparison; DeepEval provides pytest-integrated metric gates for CI — the 2026 practitioner split is promptfoo for comparison matrices, DeepEval for CI gates — *https://www.promptfoo.dev/docs/guides/evaluate-json/ and https://genai.qa/blog/promptfoo-vs-deepeval/*

### Pitfalls
- Treating inter-run agreement as a quality signal (the mistake just made): without ground truth, agreement between two pipeline variants measures output stability under prompt/input perturbation, not correctness — two pipelines can agree on hallucinations, and the better pipeline can be the one that disagrees more; no design decision is licensed by that number
- Exact-string + exact-type matching mechanically inflates disagreement: casing, articles, punctuation, alias variants ('McDonalds' vs 'McDonald's'), boundary choices, and near-synonym types all score as total errors; MUC-5/SemEval-2013 built the partial/type schemes specifically to separate benign variation from real error — always report all four schemes, not one
- Using an ad-hoc, unfrozen ontology: if the type vocabulary and entity definition drift between runs, type 'errors' are guideline noise; the ontology must be closed, written down, and validated by inter-annotator agreement BEFORE any measurement
- Iterating the prompt/pipeline on the data you report on: without a frozen held-out test set, every reported number is overfit to your iterations; freeze test after adjudication, iterate on dev only, score test once per claim
- Reporting only micro-F1 (hides collapse on rare types like books or films behind abundant songs/places) or only macro (lets a 5-item type swing the headline) — report both plus the per-type table
- Comparing pipelines on a single run: LLM/VLM decoding is nondeterministic even at temperature 0 on many APIs; run 3+ times and report mean±sd, then test significance with paired bootstrap — a raw ΔF1 without a CI is noise until proven otherwise
- Underpowered test sets: a few dozen videos cannot detect the 3-5 point F1 differences that matter; size the test set with power analysis (Card et al. 2020) — roughly 1,000+ gold entity mentions (~300 videos) for that sensitivity
- Unstratified sampling: with 53% VTT and 17% slideshows, an unstratified sample lets the easy stratum mask failure on the hard one, and pipeline comparisons (native-video vs keyframes+VTT) differ exactly along those strata — stratify and report per-stratum
- Conflating extraction error with grounding error: score disambiguation accuracy given gold mentions separately from end-to-end linking F1 (ELEVANT decomposition), or you cannot tell whether to fix the VLM or the resolver
- Ignoring NIL: a grounding module that never says 'no match' can look excellent if NILs are excluded from scoring; make NIL a first-class prediction with its own precision/recall (TAC-KBP B³+ penalizes exactly this)
- Trusting JSON-schema validity as quality: 2026 benchmarks show ≥96% structural compliance coexisting with 0.69-0.83 value accuracy — schema conformance is a precondition, not a metric
- Using an LLM judge without validation: an uncalibrated judge is a second unvalidated model; validate against ~200 dual-labeled examples to Cohen's kappa ≥0.6 and never use it where deterministic comparison works (grounding = ID equality)
- Skipping the IAA ceiling: if two humans only agree at 0.80 entity-F1 under your guidelines, a system 'achieving 0.85' means your guidelines are broken, not that the system is superhuman — publish IAA alongside system scores

## Entity-linking + grounding + calibration eval

*confidence: high*

### Verdict
The gold standard is a frozen, exhaustively-annotated ID-level gold set plus a three-layer metric stack — (1) component-decomposed entity-linking metrics (mention detection vs disambiguation vs NIL, InKB micro/macro P/R/F1 à la GERBIL/ELEVANT, with NIL scored as its own class with NIL-precision/recall), (2) an asymmetric-cost headline metric (Effective Reliability Φ_c, which pays +1 for a correct ID, 0 for NIL/abstain, and −c for a wrong ID, directly encoding "confidently-wrong beats NIL is false"), and (3) calibration + selective-prediction reporting (smECE with reliability diagram, Brier score, risk–coverage curve/AURC, and the product-facing number: coverage at ≤X% risk at the shipped threshold) — all with cluster-bootstrap 95% CIs resampled at the video level and paired-bootstrap tests for any pipeline comparison. Inter-run agreement without ground truth measures consistency, not correctness, and can never justify a design decision; the experiment must be re-run as: freeze ontology + guidelines + KB snapshots → build the gold set with double annotation + adjudication and API-verified IDs → then compare native-video vs keyframes+VTT on gold metrics with CIs.

### Method
STEP 0 — FREEZE BEFORE MEASURING. Version and freeze: (a) the entity ontology, defining each type by a Wikidata P31/P279* type-whitelist (the ad-freiburg annotation-guidelines approach) so "is this a place-entity?" is decidable, not vibes; (b) written annotation guidelines covering metonymy, alternative valid spans/IDs, and the NIL decision tree; (c) KB snapshots — Wikidata dump date, MusicBrainz DB/API date, Places retrieval dates — recorded per label so the benchmark is reproducible against a moving KB.

STEP 1 — BUILD THE GOLD SET (the answer key is IDs, not strings). (1) Stratified random sample from the 4,661-video corpus; strata = VTT-present (53%) vs absent, slideshow (17%) vs video, duration terciles. Size by CI width: 95% half-width ≈ 1.96·√(p(1−p)/n); at p≈0.8 you need ~680 graded mentions for ±3%, so target ~800–1,000 mentions overall and ≥100–200 per major entity type before trusting per-type numbers (start with a ~150-video pilot to estimate mention density and IAA). (2) EXHAUSTIVE annotation per video (every in-scope entity), never gold-from-union-of-system-outputs (pooling bias inflates recall). (3) Two independent annotators per video, disagreements adjudicated by a third; report chance-corrected IAA (Cohen's κ / Krippendorff's α) separately for mention detection and for ID assignment; the 2025 Nature Scientific Data multi-genre NER+L dataset formalizes this as gold/silver/bronze agreement tiers. (4) Every gold ID is verified against the authoritative API at annotation time: MBID via MusicBrainz lookup (verify recording vs work; use AcoustID/Chromaprint audio fingerprinting when the song is the audio track — don't gold-label from a title string), QID via Wikidata with a P31 type check, Place ID via Places Details (and store name+address+lat/lng because Google Place IDs go stale and must be refreshed). (5) NIL is two distinct labels per "Learn to Not Link": NIL-missing-entity (real entity, KB has no ID — a legitimate gold answer) vs non-entity-phrase (extraction error); the annotator must record the failed search queries before assigning NIL. (6) Seed a deliberate hard slice (cover songs, chain restaurants, common film titles) using ambiguous-name seeding as in the NEL dataset construction.

STEP 2 — METRICS, DECOMPOSED. Evaluate three sub-tasks separately, GERBIL-style: D2KB-analog (gold mentions given → grounding accuracy in isolation) and A2KB-analog (end-to-end), because otherwise extraction noise and grounding noise are confounded. Since video has no char offsets, pre-register the mention-match criterion (type must match + canonical-name match after normalization; adjudicate borderline matches) — the ReFinED convention of "InKB micro-F1 with strong matching" shows the criterion must be declared, not improvised. Report: micro AND macro precision/recall/F1; InKB metrics (gold has an ID) and NIL metrics separately — NIL-precision = correct NILs / predicted NILs, NIL-recall = correct NILs / gold NILs, NIL-F1; overall micro-accuracy where a correct NIL counts as correct (the TAC-KBP formulation); per-entity-type breakdown; ELEVANT-style error categories for every FP/FN (wrong-candidate vs NIL-predicted-as-entity vs entity-predicted-as-NIL vs detection miss). HEADLINE METRIC: Effective Reliability Φ_c (Whitehead et al., ECCV 2022): score +1 correct ID, 0 abstain/NIL-when-should-answer... precisely: +1 if answered correctly, −c if answered wrongly, 0 if abstained; report Φ_1 and Φ_10 and state the chosen c as a product judgment (a wrong durable ID silently corrupts the user's library; c=10 encodes that). Every number gets a 95% CI from a cluster bootstrap that resamples VIDEOS (mentions within a video are correlated), ≥1,000 resamples; pipeline A vs B comparisons use the paired bootstrap (Dror et al., ACL 2018).

STEP 3 — CALIBRATION + ABSTENTION. The grounding module emits P(correct) per link. (1) Split gold into dev/test; fit post-hoc calibration (temperature/Platt for continuous scores, isotonic if monotone-nonlinear) on dev ONLY. For LLM-verbalized confidence, elicit numeric probabilities with a tested prompt — Tian et al. (EMNLP 2023) show verbalized probabilities + temperature scaling cut ECE by ~50% vs token logprobs on RLHF models — but always measure, never assume. (2) Report on test: smECE with a kernel-smoothed reliability diagram via the relplot package (binned ECE is discontinuous and bin-count-gameable; if you also report classic ECE, use equal-mass bins, 10–15, and say so), Brier score (proper scoring rule, can't be gamed by confidence shaping), and the risk–coverage curve with AURC (Geifman & El-Yaniv selective-classification framing). (3) Pick the shipping threshold τ on dev to hit a target selective risk (e.g., ≤5% wrong-ID rate among emitted IDs), then report test coverage@risk≤5% — this is the honest product claim: "we attach an ID to X% of mentions and Y% of those are right; the rest we say NIL."

STEP 4 — PUBLISH LIKE A BENCHMARK. Release: dataset card (corpus stats, strata, guidelines version, KB snapshot dates, IAA per subtask, NIL taxonomy counts); the gold set + eval harness + raw per-mention system outputs; a results table per lane (Gemini Flash-Lite / Qwen3-VL) × per ingestion pipeline with columns: InKB micro-P/R/F1 (D2KB and A2KB), NIL-P/R/F1, micro-accuracy, Φ_1, Φ_10, Brier, smECE, AURC, coverage@5%-risk — each ±95% CI — plus per-type macro table and ELEVANT-style error-category breakdown. Only after this apparatus exists do you re-run native-video vs keyframes+VTT and let the paired-bootstrap deltas on Φ_c and D2KB-F1 make the design decision.

### Evidence

- GERBIL standardizes EL evaluation with micro/macro precision-recall-F1 and the InKB vs EE (emerging-entity) split, and separates experiment types so disambiguation-only (gold mentions given) is measured apart from end-to-end annotation — *https://journals.sagepub.com/doi/10.3233/SW-170286 and http://nlpprogress.com/english/entity_linking.html*
- ELEVANT auto-classifies every EL false positive/negative into 3 categories and 15 subcategories (including 'ground truth entity unknown' — predicting a KB entity where gold is NIL) and breaks results down by entity type; it is the current maintained evaluation/analysis tool — *https://aclanthology.org/2022.emnlp-demos.8/ and https://github.com/ad-freiburg/elevant and https://elevant.cs.uni-freiburg.de/*
- Existing EL evaluations are flawed by aggregate-only metrics, unclear entity/mention specification, and poor ambiguity handling; fair evaluation requires explicit guidelines and error analysis — *https://arxiv.org/abs/2305.14937 (Bast, Hertel, Prange — EMNLP 2023)*
- Concrete annotation-guideline prior art: define entities via Wikidata P31/P279* type whitelist; annotate 'Unknown' when the entity should be in the KB but isn't; allow alternative valid spans/IDs for genuine ambiguity; explicit metonymy rules — *https://github.com/ad-freiburg/entity-linking-annotation-guidelines*
- NIL mentions split into 'Missing Entity' vs 'Non-Entity Phrase', and both types materially affect NIL-prediction accuracy; the NEL dataset was built by seeding ambiguous entities and human-verifying NILs — *https://arxiv.org/abs/2305.15725 (Learn to Not Link, ACL Findings 2023)*
- TAC-KBP entity linking scored micro-averaged accuracy over queries including NIL queries, and from 2011 evaluated NIL handling via B-cubed+ clustering metrics — the canonical precedent for scoring 'correctly said no match' — *https://nlp.stanford.edu/pubs/kbp2011-entitylinking.pdf and https://tac.nist.gov/2011/KBP/scoring.html and https://tac.nist.gov//2013/KBP/EntityLinking/guidelines/KBP2013_EntityLinkingTaskDescription_1.0.pdf*
- SOTA EL papers report 'InKB micro-F1 with strong matching' and state the mention-boundary matching criterion explicitly — the reporting convention to copy — *https://arxiv.org/abs/2207.04108 (ReFinED, NAACL 2022)*
- Effective Reliability Φ_c gives +1 for a correct answer, −c for a wrong answer, 0 for abstention, explicitly encoding that a confidently-wrong answer is worse than abstaining; evaluated jointly with risk-coverage curves — *https://arxiv.org/abs/2204.13631 (Whitehead et al., Reliable VQA, ECCV 2022)*
- Selective classification formalizes the risk-coverage trade-off; AURC (area under risk-coverage curve) and coverage-at-fixed-risk are the standard metrics for abstention quality — *https://papers.nips.cc/paper/7073-selective-classification-for-deep-neural-networks (Geifman & El-Yaniv, NeurIPS 2017) and https://torch-uncertainty.github.io/generated/torch_uncertainty.metrics.classification.AURC.html*
- Binned ECE is discontinuous and bin-sensitive; smECE (kernel-smoothed) is the principled replacement, implemented in the relplot package (pip install relplot) — *https://openreview.net/forum?id=XwiA1nDahv and https://arxiv.org/html/2309.12236 (Błasiok & Nakkiran, ICLR 2024)*
- For RLHF/instruction-tuned LLMs, verbalized confidence with the right prompt plus temperature scaling is better calibrated than token logprobs, reducing ECE by ~50% relative — *https://aclanthology.org/2023.emnlp-main.330/ (Tian et al., Just Ask for Calibration, EMNLP 2023)*
- The TACL survey 'Know Your Limits' organizes abstention methods, benchmarks, and evaluation metrics for LLMs — the current framing for abstention-aware evaluation — *https://direct.mit.edu/tacl/article/doi/10.1162/tacl_a_00754/131566 and https://arxiv.org/abs/2407.18418*
- 2025 gold-standard NER+L dataset practice: multiple independent annotators, gold/silver/bronze agreement tiers, manual lookup of the most specific QID, explicit NIL handling; IAA-only gold trades recall for precision and must be reported — *https://www.nature.com/articles/s41597-025-05274-4 (Scientific Data, 2025)*

- Multimodal/short-video entity linking prior art exists to position against: AMELI (attribute-aware MEL), UniMEL (LLM-based MEL), Kuaipedia (large-scale short-video entity extraction), WikiDiverse — *https://arxiv.org/pdf/2305.14725 and https://arxiv.org/pdf/2407.16160 and https://arxiv.org/pdf/2211.00732*

### Pitfalls
- Treating inter-run agreement as accuracy: two runs (or two pipelines) can agree on the same wrong ID or the same hallucinated entity; without gold labels, agreement measures consistency, never correctness — it cannot decide native-video vs keyframes+VTT.
- Exact-string matching on entity names: conflates surface-form variation ('SZA – Kill Bill' vs 'Kill Bill by SZA') with disambiguation error; evaluation must compare at the durable-ID level, with a pre-registered mention-match criterion for the detection stage.
- No NIL option in the protocol: forces the model to always link, rewards hallucinated matches, and makes the agreement number look better than the system is; NIL must be a first-class gold label with its own precision/recall.
- Unvalidated ad-hoc ontology: if 'what counts as an entity' isn't pinned by a type whitelist and written guidelines, annotator and model disagreements about scope masquerade as extraction errors (the exact flaw Bast et al. 2023 document in famous benchmarks).
- Symmetric scoring of wrong-ID vs NIL: plain accuracy/F1 treats a confidently wrong MBID the same as an honest NIL; use Effective Reliability Φ_c (c≥10) or report selective risk so the metric matches the product harm.
- Reporting a single binned-ECE number: ECE is bin-count sensitive and discontinuous, and can be minimized by a trivially underconfident model; pair smECE with a reliability diagram, Brier score, and a risk-coverage curve.
- Calibrating, threshold-picking, and evaluating on the same split: threshold τ and calibration maps come from dev; test is touched once.
- Building gold labels from the union of system outputs (pooling): inflates recall for the pooled systems; annotate sampled videos exhaustively instead.
- Single-annotator gold with no IAA: without double annotation + adjudication and a reported kappa/alpha, the 'gold' set's own error rate is unknown and bounds nothing.
- Collapsing NIL into one class: NIL-because-KB-is-missing-the-entity and NIL-because-not-an-entity have different causes and different fixes (KB coverage vs extraction precision); label both.
- Bootstrap over mentions instead of videos: mentions within one video are correlated (same audio, same caption), so mention-level resampling understates CI width; cluster-resample videos.
- Ignoring KB drift: Wikidata/MusicBrainz grow and Google Place IDs go stale; a benchmark without KB snapshot dates is unreproducible and its NIL labels rot.
- Comparing pipelines by point estimates: a 2–3 point F1 gap on a few hundred mentions is routinely within the 95% CI; use paired bootstrap and report the CI of the delta.

## Annotation science / golden-set (solo)

*confidence: high*

### Verdict
The gold standard is the corpus-annotation lifecycle from computational linguistics (Pustejovsky & Stubbs' MATTER/MAMA cycle plus TAC KBP entity-linking practice), adapted for one annotator: write a versioned codebook BEFORE labeling anything, anchor the ontology and NIL policy in TAC KBP EDL conventions, pilot on 30-50 videos to stabilize the guidelines, then build a stratified ~500-video gold set (strata: VTT/no-VTT, slideshow/video, duration) split eyes-off into dev (~100-150, for prompt tuning) and test (~350-400, touched only at release time). Label via LLM pre-annotation from a DIFFERENT model family than the pipeline under test, imported as suggestions into Argilla (HF-owned, free) or Label Studio, with every grounding ID verified by actually opening MusicBrainz/Wikidata/Google Maps. Bound the solo-annotator biases explicitly: a blind-from-scratch control subsample (15-20%) quantifies pre-annotation anchoring, a ≥2-week test-retest pass (10-15%, prior labels hidden) gives intra-annotator Krippendorff's alpha (target ≥0.8, 0.667 floor), and a 50-100-video second-annotator seed gives a publishable true IAA number. Measure agreement with pairwise F1 for mentions (kappa is undefined without negatives — Hripcsak & Rothschild 2005) and Krippendorff's alpha for type/NIL/ID decisions; never raw percent agreement, which is documented to overstate chance-corrected agreement by 33-41.2pp across all 21 LLM judges tested (arXiv 2606.19544). Report accuracy with Wilson 95% CIs (±3.5pp at n=500, p≈0.8) per stratum and overall. The experiment you ran — inter-run agreement with no ground truth, ad-hoc prompt, ad-hoc ontology, exact-string matching — measured reliability, not validity: two configurations can agree perfectly on the same wrong answers, and that number cannot rank pipelines (Thakur et al. showed judges with 34-point LOWER human alignment can still rank systems better).

### Method
PHASE 0 — Ontology from prior art (0 labels yet). Define the entity model on existing schemas, not ad-hoc: entity types mapped to Wikidata classes/Schema.org; per-type grounding target (song→MusicBrainz MBID via recording/work distinction, place→Google Place ID, film/book/person→Wikidata QID); mention vs. entity distinction; NIL policy copied from TAC KBP EDL guidelines (link-or-NIL decision, NIL gets its own ID and NILs referring to the same real thing cluster together — TAC KBP introduced NIL clustering in 2011). Decide the unit of evaluation now: the (video, mention, type, ID-or-NIL) tuple.

PHASE 1 — Codebook first (MATTER cycle: Model precedes Annotate). Write annotation guidelines: decision rules, positive AND negative examples per type, edge cases specific to this corpus (background music vs. featured song; entity only on-screen as text vs. spoken; slideshow frames; implied-but-unnamed restaurants; 'groundable in principle but ambiguous' cases). Version the document; every future change gets a changelog entry.

PHASE 2 — Pilot (MAMA subcycle). Annotate 30-50 videos; log every hesitation as a guideline amendment; iterate model↔annotation until a full batch produces no new rules. Discard or re-annotate pilot items under the final guideline version — pilot labels never enter the gold set.

PHASE 3 — Stratified sampling. From the 4,661-video corpus, draw a stratified random sample on variables that plausibly change difficulty: VTT present (53%) vs. absent, slideshow (17%) vs. video, duration terciles. Proportional allocation, but oversample rare strata to ≥50 items each so per-stratum accuracy is reportable; reweight for the overall figure.

PHASE 4 — Size by target CI (plan with n = z²·p(1−p)/E², report with Wilson): at expected accuracy ~0.8: n=246→±5pp, n=384→±4pp, n=500→±3.5pp, n=683→±3pp at 95%. Target 500 gold videos (solo-feasible: ~3-5 min/video with pre-annotation ≈ 30-40 hours). Mentions cluster within videos, so compute CIs on the mention-level metric with a cluster (per-video) bootstrap — the clustered-standard-error recommendation in Miller's 'Adding Error Bars to Evals' (arXiv 2411.00640).

PHASE 5 — Solo annotation protocol. (a) Pre-annotate with an LLM from a DIFFERENT family than both product lanes (e.g., Claude if the pipeline is Gemini/Qwen) to avoid correlated errors and self-preference; import as suggestions into Argilla or Label Studio. (b) Human pass: verify/correct every suggestion, add missed entities, and confirm every ID by opening the actual MusicBrainz/Wikidata/Places record — never accept an ID by name similarity. (c) Anchoring-bias control: annotate a random 15-20% subsample from scratch, blind to pre-annotations; the recall gap between blind and assisted passes IS your measured pre-annotation bias (pre-annotation mainly suppresses recall — you don't add what the model missed; clinical-NER studies found 14-21% speedup with no detected bias, but their bias checks were weak because all annotators saw the same pre-labels). (d) Test-retest: ≥2 weeks later, re-annotate 10-15% with prior labels hidden; compute intra-annotator agreement. (e) External seed: pay/recruit 1-2 people to double-annotate 50-100 videos under the codebook for a true IAA figure to publish. (f) Adjudicate every disagreement by writing a rule into the guidelines — never silently pick.

PHASE 5b — Metrics: pairwise F1 for mention spans (kappa needs a defined negative count that span tasks lack — Hripcsak & Rothschild, JAMIA 2005; also GATE and Prodigy docs' standard); Krippendorff's alpha for categorical decisions (type, NIL-vs-link, chosen ID) — handles missing data and any number of coders; Cohen's kappa acceptable for exactly two complete coders. Thresholds: alpha ≥0.800 reliable, 0.667-0.800 tentative-only (Krippendorff); report the coefficient AND raw agreement, never raw agreement alone. If agreement on a category is below threshold, fix the guidelines and re-annotate that category — do not publish it.

PHASE 6 — Leakage protocol. Split BEFORE any prompt iteration: dev ~100-150 (tune prompts/ontology freely), test ~350-400 eyes-off — evaluated at most once per major pipeline version, error analysis on dev only, every test-set access logged. Prompting choices are hyperparameters; optimizing them against the reporting set is classic overfitting (Microsoft's Medprompt team held out an 'eyes-off' 20% split for exactly this reason). Refresh/extend the test set over time.

PHASE 7 — LLM-judge validation before any automated scoring. If an LLM later auto-scores grounding at scale, validate it first on 100-200 human-adjudicated items; require chance-corrected kappa (≥~0.7-0.8), not percent agreement — raw agreement overstated kappa by 33-41.2pp in ALL 21 judges across 118 runs / 541k judgments ('Reliability without Validity', arXiv 2606.19544) — and re-validate on distribution shift. High percent agreement can also be an artifact of easy/imbalanced samples (Elangovan et al., arXiv 2410.03775).

PUBLISH: test-set accuracy with Wilson 95% CIs, per-stratum and weighted overall; entity-extraction F1 and grounding accuracy@ID separately; NIL precision/recall separately; the codebook version; the IAA/intra-annotator numbers; the blind-subsample bias bound.

- Publishing a single overall accuracy with no CI and no strata: a 100-item set gives roughly ±8pp at p=0.8 — too loose to defend a moat claim; and pooled accuracy hides that no-VTT or slideshow items may be far worse

- Skipping NIL policy: a benchmark that only scores linkable entities rewards overconfident linkers; NIL precision/recall must be a first-class reported number (TAC KBP convention)

## Prompt/pipeline optimization as science

*confidence: high*

### Verdict
The gold standard is instrument-before-experiment. A rigorous team never compares pipeline variants until the measurement instrument — ontology + output schema + annotation guidelines + gold dev/test sets + matcher + metric — is built and validated, because an ablation's result is only as trustworthy as the instrument scoring it. Your inter-run agreement number is a reliability statistic about an unvalidated instrument: two ingestion paths can agree on the same wrong entities, and an exact-string matcher's bias (surface-form variance in entity names is huge) is unknown and plausibly larger than the native-vs-VTT effect you were trying to measure. This is precisely the reliability≠validity confusion the construct-validity literature warns about (arXiv:2511.04703, a 445-benchmark NeurIPS review), and Anthropic's own engineering team showed why it's fatal: fixing a rigid grader alone moved a model's measured score from 42% to 95% — grader/matcher artifacts routinely dwarf true system differences. The correct sequence is: problem → ontology/schema v0 from manual data inspection → annotation guidelines → gold set with IAA (pairwise F1, not kappa, for entity spans) → metric+matcher validated against humans → prompt iterated on dev only under regression testing → freeze the whole instrument → one-factor ablations on dev with paired bootstrap CIs → final headline number reported once on the sealed test set. Your run isn't worthless — it validated plumbing, cost, and latency — but its number must be quarantined and the native-vs-VTT ablation rerun after the instrument exists. For Commonplace this discipline is doubly load-bearing: the moat IS published grounding accuracy, so the eval instrument is the product's core asset, and entity linking already has field conventions to adopt wholesale (GERBIL-style micro/macro P/R/F1 with InKB vs. full-corpus NIL handling, ELEVANT-style error taxonomies) rather than invent.

### Method
PHASE 0 — Define the construct (½ day). Write down, in one page, what "an entity worth grounding" means: which real-world referent types count (song, place, film, product, book, person), what a mention is (spoken, on-screen text, shown visually, in caption), and what NIL means (no durable ID exists vs. resolver failed). This is construct validity — the measure must represent the phenomenon (arXiv:2511.04703). Everything downstream is versioned against this.

PHASE 1 — Ontology + output schema v0 from manual inspection (1–2 days). Watch ~50 stratified videos yourself and hand-list every entity before any model runs (Hamel: "you are doing it wrong if you aren't looking at lots of data"). Draft the ontology (types, attributes, target ID namespace per type: MBID/QID/PlaceID) and express the output contract as a JSON Schema used with provider constrained decoding (Gemini response_schema / OpenAI strict mode) — schema validity becomes a hard gate, not a metric (JSONSchemaBench, arXiv:2501.10868). Keep the schema flat and enum-typed; Gemini/OpenAI constrained decoding guarantees syntactic validity but NOT semantic correctness, so semantic checks stay in the eval.

PHASE 2 — Annotation guidelines + gold set (the single most important artifact; ~1 wk of founder time spread out). Write guidelines with positive AND negative examples per entity type and explicit edge-case rules (cover: entity mentioned but not endorsed, background music vs. featured song, franchise vs. specific film, slideshow text). Pilot: double-annotate 30–50 videos (you + a second pass — a strong LLM as second annotator with you adjudicating disagreements is acceptable at solo-founder scale, but disagreements are resolved by YOU and fed back into the guidelines). Measure inter-annotator agreement with pairwise F1 (Cohen's kappa is inappropriate for span/set-valued entity tasks); iterate guidelines until agreement is stable — high agreement under vague guidelines just means consistent wrongness. Then annotate the full gold set STRATIFIED to corpus composition (~53% VTT / ~17% slideshow / duration strata / entity-type coverage): dev ≈ 100–150 videos, test ≈ 100–150 videos. Size by MENTIONS not videos: at ~3–6 mentions/video that yields 400–800 mentions per split, enough for ±4–5% CI on overall accuracy and ~50+ mentions for the top types. The test set is sealed — never opened, never read, never scored against until the final report (Anthropic starts evals at "20–50 simple tasks drawn from real failures"; OpenAI: define success criteria and a ground-truth dataset covering the production distribution BEFORE optimizing).

PHASE 3 — Validate the metric + matcher (2–3 days). The matcher decides when a predicted entity counts as matching gold. For the grounding stage this is trivial and deterministic: ID equality (MBID=MBID). For the extraction stage, exact-string is banned; use normalized matching (casefold, unicode-normalize, strip articles) plus a validated fuzzy threshold or an LLM-judge — and VALIDATE the matcher itself: run it on ~100 human-labeled match/non-match pairs and report its precision AND recall separately (Hamel: raw agreement is misleading under class imbalance). Adopt entity-linking conventions: micro + macro P/R/F1 per entity type; grounding accuracy among linked mentions; InKB metrics vs. full-corpus metrics so NIL is scored explicitly (GERBIL, Röder et al.; ELEVANT for fine-grained error categories). Choose deterministic graders wherever possible, LLM graders only where necessary (Anthropic).

PHASE 4 — Iterate prompt (+schema +ontology) on DEV ONLY. Loop = run → read transcripts → categorize every error (missed entity / hallucinated entity / wrong type / wrong ID / bad NIL) → fix the biggest bucket → rerun (Hamel's error-analysis loop; the 2026 "When Generic Prompt Improvements Hurt" paper, arXiv:2601.22025, shows generic prompt additions are non-monotonic — the same change improved strict extraction 13%→100% while collapsing another task 26/30→9/30 — so every prompt change is a regression risk to be tested, never assumed good). Harness: promptfoo or DeepEval config with the gold dev set + validated matcher as assertions, run in CI so regressions surface per-change. Ontology/guideline changes are allowed in this phase but must be versioned and trigger re-annotation of affected gold items. DSPy MIPROv2/GEPA is the right tool ONLY after this phase's prerequisites exist — a trusted metric and 50–500 labeled examples (DSPy's own recommendation) — and at your scale (one extraction prompt, one model call) hand iteration guided by error analysis captures most of the gain; reach for MIPROv2/GEPA if you plateau and want the last few points, running it on a train split carved from dev, never on test.

PHASE 5 — FREEZE. Tag prompt vX + schema vX + ontology vX + guidelines vX + matcher vX + metric definition as the instrument. No further edits during experiments.

PHASE 6 — Ablations on dev with the frozen instrument. Now — and only now — run native-video vs. keyframes+VTT, Flash-Lite vs. Qwen3-VL, with/without VTT. Rules: (a) one factor per comparison, everything else identical — same videos, same frozen prompt/schema, temperature 0, same decoding constraints, same matcher (controlled-ablation standard: identical data/splits/protocol or the effect isn't attributable); (b) score BOTH arms against gold with the validated metric — never against each other; (c) paired design: same videos in both arms, compute per-video score deltas, paired bootstrap with B≥1000 resamples, 95% CI from the 2.5th/97.5th percentiles, difference is real only if the CI excludes zero (standard NLP protocol, arXiv:2511.19794); (d) LLM nondeterminism persists even at temp 0, so run ≥3 repeats per arm and report mean±sd — a single run is a sample size of one; (e) decide on the CI plus the cost/latency Pareto frontier, not point estimates; stratify results by VTT-present/absent and slideshow/video since the ablation's effect almost certainly differs by stratum.

PHASE 7 — Final report on the sealed test set, once. The published benchmark number (the moat) comes from a single scoring run of the frozen winning pipeline on test. After publication, the old test set is burned as a dev-adjacent asset; refresh with newly annotated videos for the next cycle (rotate ~20% per major model update to fight staleness).

- Define success criteria and build a ground-truth dataset covering the production input distribution BEFORE optimizing; combine automated evals for iteration with periodic human review for calibration — *https://developers.openai.com/api/docs/guides/evaluation-best-practices*
- Generic prompt 'improvements' are non-monotonic across tasks: the same intervention improved strict extraction (Qwen 13.3%→100%) while collapsing RAG citation compliance (26/30→9/30); 'prompt changes should be treated as potential regression risks'; proposes Define→Test→Diagnose→Fix loop against curated golden sets — *https://arxiv.org/html/2601.22025v2*
- DSPy MIPROv2 recommends 50–500 labeled examples, jointly optimizes instructions + few-shot demos via Bayesian search, and defaults to an 80% validation carve-out from trainset — i.e., a trusted metric and labeled data are prerequisites for automatic prompt optimization, not outputs of it — *https://dspy.ai/api/optimizers/MIPROv2/ and https://deepwiki.com/stanfordnlp/dspy/4.4-miprov2:-instruction-and-parameter-optimization*
- GEPA optimizes via natural-language reflection on execution traces + Pareto-based evolutionary selection, achieving gains with fewer rollouts than RL-style methods; MIPROv2 'may overfit to the provided examples' — reinforcing the need for a held-out split during optimization — *https://medium.com/@melikedulkadir/prompt-optimization-with-dspy-gepa-explained-with-python-examples-e85f4ea17a8d and https://oss.vicente.services/dspy.rb/optimization/prompt-optimization/*
- Standard NLP system-comparison protocol: paired bootstrap resampling over per-item score differences, B=1000 replicates, 95% CI from 2.5th/97.5th percentiles, improvement significant only if the CI excludes zero — *https://arxiv.org/html/2511.19794v1 and https://medium.com/ai-enthusiast/comparing-nlp-models-with-confidence-the-paired-bootstrap-test-explained-c9a88532ea3d*
- A valid ablation isolates exactly one variable with identical data, splits, seeds, hyperparameters, and evaluation protocol; a single-run result 'is a point estimate with unknown uncertainty; publishing it as a finding is publishing a sample size of one' — *https://www.emergentmind.com/topics/controlled-ablation-study and https://www.bestaiweb.ai/from-baselines-to-factorial-design-prerequisites-and-core-components-of-ablation-experiment-design/*
- Systematic review of 445 LLM benchmarks (42 authors, NeurIPS 2025 D&B) found pervasive construct-validity failures — 'patterns related to the measured phenomena, tasks, and scoring metrics which undermine the validity of the resulting claims' — reliability (agreement) is not validity; 8 prescriptive recommendations for benchmark construction — *https://arxiv.org/abs/2511.04703*
- High inter-annotator agreement under poorly defined guidelines indicates annotators 'consistently apply the same incorrect interpretation, not that annotations are correct'; Cohen's kappa is inappropriate for NER-style span/set annotation — pairwise F1 is the accepted alternative; continuous calibration on shared reference sets maintains quality — *https://claru.ai/glossary/inter-annotator-agreement*
- Entity-linking evaluation has standardized conventions to adopt, not invent: GERBIL's micro/macro precision-recall-F1 with InKB vs. full-corpus measures for explicit NIL handling; micro-F1 weights mention-heavy documents, macro-F1 averages per document — *https://journals.sagepub.com/doi/10.3233/SW-170286 and http://nlpprogress.com/english/entity_linking.html*
- ELEVANT provides fully automatic fine-grained entity-linking evaluation with typed error categories (e.g., wrong-candidate vs. NIL errors) — the reference model for the error-analysis buckets in Phase 4 — *https://arxiv.org/pdf/2208.07193*
- Constrained decoding (OpenAI strict mode, Gemini response_schema) compiles JSON Schema to token-level masks giving guaranteed schema-valid output; JSONSchemaBench evaluated six frameworks on 10K real-world schemas — syntactic validity is solvable as a gate, so eval effort belongs on semantic correctness — *https://arxiv.org/html/2501.10868v1 and https://techsy.io/en/blog/llm-structured-outputs-guide*
- Test-set discipline in 2026 practice: keep a sealed holdout never inspected until release; run optimization loops on a separate split so the optimizer cannot memorize the eval; rotate ~20% of eval examples on major model updates; regenerate regression baselines on merge and run deltas in CI (promptfoo pattern) — *https://futureagi.com/blog/prompt-regression-testing-2026/ and https://medium.com/@Quaxel/when-llm-benchmarks-start-lying-7722edef31e8*
- Eval-driven prompt development is 'pytest for prompts': versioned declarative suites (promptfoo, DeepEval) scoring old and new prompts on the same examples with a statistical delta, integrated into CI so regressions surface at review time, not post-deploy — *https://www.adaline.ai/blog/best-prompt-testing-tools-in-2026 and https://www.braintrust.dev/articles/best-prompt-evaluation-tools-2025*

### Pitfalls
- Treating inter-run agreement as a quality signal (your exact error): agreement is reliability, not validity — two pipeline variants can consistently agree on the same wrong entities, and without ground truth the direction and magnitude of bias are unknowable, so the number cannot support a design decision
- Running the ablation before validating prompt+ontology+matcher: the comparison confounds instrument noise (prompt ambiguity, ontology drift, matcher false-negatives) with the manipulated variable; the observed delta is uninterpretable and the experiment must be rerun after Phase 5 — the concrete cost of the ordering error
- Exact-string matching as the extraction matcher: entity surface forms vary wildly ('Blank Space' vs 'blank space by taylor swift'), so exact match systematically undercounts agreement/recall with unknown per-arm bias — potentially larger than the native-vs-VTT effect itself; the matcher is part of the instrument and must itself be validated (P/R vs human judgments)
- Iterating the prompt against the same set you report on: sealed test set, opened once for the final published number; all iteration and all ablations happen on dev; if using DSPy optimizers, carve a train split from dev so the optimizer never touches even dev-eval directly
- Changing more than one factor per ablation arm (e.g., tweaking prompt wording while switching ingestion path): hold videos, prompt, schema, temperature, decoding constraints, and matcher identical; vary exactly one thing
- Single-run point estimates: LLM outputs vary across runs even at temperature 0; run >=3 repeats per arm, use a paired design on identical videos, and report paired-bootstrap 95% CIs — a delta whose CI crosses zero is noise, not a finding
- Ad-hoc ontology invented mid-experiment: the ontology is part of the measurement instrument; it must be versioned, frozen before ablations, and changes must trigger re-annotation of affected gold items
- Using Cohen's kappa for entity-span annotation agreement (it has no natural chance-agreement model for set-valued outputs); use pairwise F1 between annotators
- Assuming generic prompt 'improvements' transfer: documented cases of the same change improving one task 13%->100% while collapsing another 26/30->9/30; every prompt change is a regression candidate to be tested on the full dev suite
- Unstratified gold set: with ~53% VTT, ~17% slideshows, the dev/test sets must mirror those strata or the ablation's headline number hides opposite-direction effects per stratum (VTT ablation is meaningless on the no-VTT stratum)
- Scoring NIL implicitly: adopt GERBIL's InKB vs full-corpus metric split so honest-NIL behavior is measured, not penalized or ignored — for Commonplace, NIL precision is part of the published moat
- Reaching for DSPy/MIPROv2 before the prerequisites exist (validated metric + 50-500 labeled examples): automatic prompt optimization amplifies whatever metric you give it; with a broken matcher it optimizes the wrong thing faster
- Treating schema-valid JSON as evidence of correctness: constrained decoding guarantees syntax, not semantics; keep schema validity as a binary gate and spend eval effort on semantic P/R/F1

## Concepts / subjects / topics

*confidence: high*

### Verdict
Model the concept/subject layer as its OWN thin SKOS spine — one skos:Concept node per durable idea / theme / subject / field / skill / occupation / service that you own — with each node skos:exactMatch-linked to a durable external authority, attached to the Referent (never the Save) via a dcterms:subject / Wikidata-P921 "is-about" edge. Treat it as categorically different from named-entity linking: an ENTITY is a rigid individual you resolve to ONE instance ID (score = exact match); a CONCEPT is a class/topic you resolve to a vocabulary node where several answers are defensible and near-misses are partly right (score = set-based, hierarchical, rank-aware — never exact match). Ground concept IDENTITY primarily to the Wikidata CLASS item (P31/P279-class discipline, CC0, the SAME KB as your entities), crosswalked to LCSH for a governed broader/narrower tree, with MeSH for the health slice and ESCO/O*NET for skills and occupations; grade the coarse "field/area-of-life" bucket with a CLOSED facet (OpenAlex Topics or IPTC Media Topics) as classification, not linking. Publish TWO moat numbers, both benchmarked to a human inter-indexer ceiling: concept-identity accuracy (micro/macro P/R/F1 + honest NIL vs a gold set) and aboutness accuracy (LCA-F / hierarchical partial credit + F1@k + nDCG@k). The decidable rule is a 3-way cascade: a rigid individual is an ENTITY (instance ID); a general kind with a confident authority node is a CONCEPT (subject vocabulary); neither is a free TAG (NIL, promotable when it recurs).

### Model
NODE & TYPE. Introduce commonplace:Concept (a subclass of skos:Concept) in its own skos:ConceptScheme — the "concept/subject spine." One node per durable idea/theme/subject/field/skill/occupation/service (ADHD, flow state, stoicism, sourdough hydration, progressive overload, "closing loops"). Each node carries: skos:prefLabel + skos:altLabel (the synonym ring: ADHD / ADD / "attention deficit"); skos:definition; skos:broader/narrower/related SEEDED from LCSH BT/NT/RT and Wikidata P279; and — the load-bearing part — SKOS MAPPING properties to external authorities (skos:exactMatch to a Wikidata CLASS QID; closeMatch/exactMatch to LCSH URI, MeSH DUI, ESCO/O*NET URI, OpenAlex topic), each mapping annotated with confidence + provenance + timestamp. This is SKOS's textbook interoperability role: you own a stable local spine, you never hard-depend on one volatile external KB, and NIL is a first-class value (no exactMatch = honestly ungrounded). RELATION TO NAMED ENTITIES (the split). An entity node is an individual — a rigid designator with P31 "instance-of" character (a specific restaurant, this song, that film), resolved to ONE instance ID. A concept node is a class/kind with P279 "subclass-of" character (an ontological "class," where named entities are "individuals," per Hedden). Same string can play both roles: one Wikidata item can be used as an instance elsewhere and as a subject here — so the concept node points at the item in its class/subject role, decided by ROLE not string. WEMI/FRBR COMPOSITION. Aboutness is a property of the durable Work/Referent, not the Save: Referent --isAbout (modeled on dcterms:subject / Wikidata P921 "main subject")--> Concept; Post and Save inherit. Full chain: Save -> Post -> Referent -> isAbout -> Concept(SKOS) -> exactMatch -> wd:Q___ (+lcsh +mesh +esco). FACETED (RANGANATHAN) COMPOSITION. Concepts are orthogonal to facets: facets answer "what ASPECT" (a Subject/Field facet, a Skill facet, an Occupation facet, a topical Personality facet); concept nodes POPULATE those pigeonholes. The coarse CLOSED "field" facet (OpenAlex/IPTC) and the open fine-grained concept spine coexist — the facet is the slot, the concept is the durable content. CLAIMS ARE NOT CONCEPTS. A thesis ("cable lateral raises isolate the medial delt better") is a proposition; model it as a Claim object whose ARGUMENT SLOTS (lateral raise, medial deltoid, muscle isolation) are concept nodes from this spine. The claim STRING is scored by faithfulness; its concepts by grounding — do not force the claim into subject linking. THE DECIDABLE RULE (per normalized mention / aboutness candidate) — a 3-way cascade with two orthogonal tests: (1) RIGIDITY/CARDINALITY test (individual vs kind): "are there many co-existing Xs / is X a type of thing?" If NO (one specific Joe's Pizza; this exact song) -> INDIVIDUAL -> ENTITY -> instance ID (Place ID / MBID / QID-as-instance). This is the P31 test. (2) If it is a kind/idea/topic/skill/occupation/field (P279 character), apply the GROUNDABILITY test: does a licensed concept authority contain a node above confidence threshold tau? YES -> CONCEPT -> ground to the subject vocabulary. (3) NO authority node above tau (emergent slang: "cortisol face," "body doubling," hyper-specific phrasing) -> FREE TAG -> NIL to authorities, queued for promotion into the controlled spine when it recurs and stabilizes. Edge rule: a proper name used generically/as a topic (Stoicism, CrossFit-as-training-style) is scored as a CONCEPT in its subject role and may exactMatch the same Wikidata item the entity layer uses — role, not string, decides.

### Grounding & eval
GROUNDING STACK (defended, layered — each type to its RIGHT target; distinct from entity instance-linking). Concept IDENTITY primary anchor = Wikidata CLASS item: CC0, free API, unmatched coverage of everyday/social-video vernacular (ADHD, flow, stoicism, sourdough) and the SAME KB already used for your named entities, so one grounding pipeline; link to the item in its class/subject role (P279/P31-class), NIL when no confident item. Governed hierarchy backbone = LCSH (id.loc.gov): public domain, SKOS/RDF via content negotiation + bulk download (no SPARQL); Wikidata items commonly carry the LCSH id (P244), so crosswalk Wikidata->LCSH cheaply and inherit a disciplined broader/narrower tree for browse/roll-up/query-expansion. Health specialist = MeSH (NLM, public domain, RDF+SPARQL at id.nlm.nih.gov) for the biomedical slice (ADHD, cortisol, sleep hygiene) with a clean tree + rich entry-term synonymy. Skills/techniques = ESCO skills (SKOS Linked Open Data, free API, 13,485 skills, 27 languages); Occupations/jobs = ESCO occupations (2,942) and/or O*NET-SOC (CC-BY 4.0, ~900 US profiles, free web services) — the RIGHT targets for skill/occupation types, far better than generic Wikidata. Coarse "field/area-of-life" facet (CLOSED classification, NOT identity linking) = OpenAlex Topics (CC0 REST, ~4,500 topics in domain>field>subfield>topic, every topic has a Wikipedia/Wikidata page) OR IPTC Media Topics (SKOS, royalty-free with attribution, editorial framing). REJECT as shippable grounding targets: Dewey (DDC) and UDC — proprietary (OCLC / UDC Consortium), not licensable for a solo commercial product; GND is CC0 and benchmarked (SemEval-2025, 200k subjects) but German-national/German-primary -> reference only, not primary for English short-video. EVAL — THREE REGIMES with a HARD grounds-vs-faithfulness split. (A) Concept-IDENTITY accuracy — GROUNDS to an authority, so report accuracy-vs-authority: for each grounded concept mention, is the canonical node correct? micro/macro Precision/Recall/F1 over mentions vs a human gold set, PLUS explicit NIL accuracy (did we correctly abstain?). This is looser than NEL — allow parent/child credit via the hierarchy (a sibling/parent is mostly-right, not zero). This is the concept half of the moat number. (B) ABOUTNESS / subject-SET accuracy — multi-label subject indexing: predicted subject set vs gold set scored with (i) set-based micro/macro-F1, (ii) HIERARCHICAL partial-credit measures hP/hR/hF and LCA-F (Kosmopoulos et al.; BioASQ's official measures are micro-F1 + LCA-F) that reward near-misses and penalize distant errors more, and (iii) rank-aware F1@k and nDCG@k (Annif / SemEval-2025 practice). EXPLICITLY reject subset/exact-match accuracy as the headline: in a large label space it scores "all-but-one correct" as a total miss, and aboutness has multiple defensible labelings, so exact match is simply the wrong metric. (C) HUMAN CEILING + relevance judgment: inter-indexer consistency is inherently low, so publish against an inter-annotator ceiling and adopt SemEval-2025 LLMs4Subjects' qualitative protocol — a judge marks each predicted subject correct / technically-correct-but-irrelevant / incorrect (Y/I/N), reported both as "Y+I" and "Y-only." Reality check for expectations: in that 2025 shared task NO system exceeded F1@5 ~ 0.35 and traditional XMTC (Annif) beat pure-LLM subject assignment — so the moat is being HONEST + MEASURED + hierarchically fair, not chasing a high flat-F1 the field itself cannot hit. WHAT DOES NOT GROUND (state plainly): the coarse field facet (OpenAlex/IPTC) is scored as CLOSED-SET classification (accuracy/macro-F1), not authority-linking; CLAIMS/takeaways/advice are scored by FAITHFULNESS (is the proposition entailed by the video? NLI/human judgment) with their argument concepts grounding via (A); free TAGs are NIL by construction, measured by retrieval utility/consistency, never scored against an authority.

### Evidence
- Entity linking in the general case links mentions not only to named entities but to concepts in a knowledge base; Wikification returns 'Null' when a mention cannot be linked — establishing concept-mention linking with honest NIL as an existing task. — *https://en.wikipedia.org/wiki/Entity_linking*
- Wikidata formally separates instance-of (P31) from subclass-of (P279): an item is an instance if it has P31, a class if it has P279 or is a P31 value — the formal basis for the ENTITY-vs-CONCEPT (individual-vs-class) split and the decision rule. — *https://www.wikidata.org/wiki/Property:P31*
- Wikidata P921 'main subject' is the standard property for 'the primary topic of a work or act of communication' — the model for the Referent-level is-about (aboutness) edge, alongside dcterms:subject. — *https://www.wikidata.org/wiki/Property:P921*
- In knowledge organization, named entities correspond to ontology 'individuals' while generic concepts are 'classes' — two registers that must be grounded and scored differently. — *https://www.hedden-information.com/taxonomies-vs-ontologies/*
- OpenAlex Concepts are DEPRECATED and replaced by Topics: a 4-level domain>field>subfield>topic hierarchy with ~4,500 topics, each mapped to a Wikipedia and/or Wikidata page plus ~10 keywords; the full dataset is CC0. — *https://www.michelepasin.org/blog/2024/09/27/open-alex-topics/index.html*
- The complete OpenAlex dataset (including Topics) is free under the CC0 license, served via a REST API. — *https://developers.openalex.org/*
- LCSH is published as public-domain SKOS/RDF at id.loc.gov, available per-record via content negotiation and as bulk RDF downloads (no SPARQL endpoint) — usable as a governed broader/narrower subject backbone. — *https://id.loc.gov/*
- IPTC Media Topics are published as SKOS and can be used at any stage of a workflow royalty-free, provided IPTC copyright is attributed — a license-friendly closed editorial topic facet. — *https://iptc.org/standards/media-topics/*
- SemEval-2025 Task 5 (LLMs4Subjects) targeted the GND subject vocabulary (200,035 subjects); GND is CC0 but German-national/German-primary, so it is reference-only for an English product. — *https://arxiv.org/html/2504.07199*
- ESCO is SKOS Linked Open Data with a free web-service API: 2,942 occupations and 13,485 skills across 27 languages — the right specialist grounding target for skills and occupations. — *https://esco.ec.europa.eu/en/use-esco/use-esco-services-api/esco-web-service-api*
- O*NET content is licensed CC-BY 4.0 with free web services and ~900 occupation profiles — a US occupations authority usable in a commercial product with attribution. — *https://www.onetonline.org/help/license*
- BioASQ's official large-scale semantic-indexing measures are micro-averaged F-measure (MiF) and Lowest Common Ancestor F-measure (LCA-F); the MeSH hierarchy is scored with hP/hR/hF and LCA-P/R/F — the standard for hierarchical subject-indexing eval. — *https://pmc.ncbi.nlm.nih.gov/articles/PMC7148078/*
- Kosmopoulos et al. (2015) define hierarchical measures P_LCA/R_LCA/F_LCA using the lowest common ancestor to give graded partial credit for near-miss subject predictions. — *https://link.springer.com/article/10.1007/s10618-014-0382-x*
- Annif (National Library of Finland) evaluates automated multi-label subject indexing with rank-aware metrics F1@5 and nDCG — the operational template for aboutness scoring. — *https://journal.code4lib.org/articles/16719*
- SemEval-2025 Task 5 used F1@5, F1@50, nDCG@10 and recall PLUS a human Y/I/N judgment (correct / technically-correct-but-irrelevant / incorrect); no system exceeded F1@5 ~ 0.35 and traditional XMTC (Annif) beat pure-LLM subject assignment — a reality check that subject indexing is graded, hard, and must be benchmarked to a human ceiling. — *https://arxiv.org/html/2504.19675v1*
- Subset/exact-match accuracy is too strict for large multi-label label spaces (predicting all-but-one correct scores as a miss); example-based metrics, micro/macro-F1, and Jaccard give the appropriate partial credit. — *https://scikit-learn.org/stable/modules/model_evaluation.html*
- SKOS mapping properties (exactMatch/closeMatch/broadMatch/relatedMatch) are the standard mechanism to link a locally owned concept scheme to external authorities without hard-depending on any single KB. — *https://www.w3.org/TR/skos-reference/*

### Pitfalls
- Metric mismatch is the #1 trap: scoring concept/subject assignment with entity-style exact-ID accuracy will make a genuinely good system look broken — subjects need set-based + hierarchical (LCA-F) + rank-aware (F1@k, nDCG@k) metrics, benchmarked to a human inter-indexer ceiling.
- Wikidata's P279/P31 graph is noisy and inconsistent (cycles, class-as-instance errors); do NOT treat it as a clean subject tree — use it for identity + everyday-concept coverage, and borrow LCSH/MeSH/ESCO for the disciplined broader/narrower hierarchy.
- Vocabulary currency: social-video vernacular ('body doubling', 'cortisol face', 'girl dinner') outruns LCSH/MeSH/OpenAlex by years — you MUST keep the free-tag overflow plus a governed promotion pipeline, or you will NIL your most-saved emergent topics.
- Aboutness belongs on the Referent/Work, not the Save — attaching subjects to each Save duplicates and desyncs them; put dcterms:subject / P921 on the Referent and let Post and Save inherit.
- Pre-coordination mismatch: LCSH strings are pre-coordinated ('Cooking, American — 19th century') while your concepts are post-coordinated atoms — map to decomposed LCSH components, do not try to match whole headings.
- There is no single gold truth for subjects — build the gold set with multiple annotators and report the inter-indexer agreement/ceiling; a single annotator understates real accuracy and hides that many 'wrong' predictions are defensible (use the Y/I/N relevance judgment).
- License traps: Dewey (DDC) and UDC are proprietary — never ship them as grounding targets; Wikidata/OpenAlex/GND are CC0, LCSH/MeSH are public domain, O*NET is CC-BY (attribution required), IPTC royalty-free with attribution.
- The confidence threshold tau governs the CONCEPT-vs-TAG boundary and directly trades precision (moat credibility) against coverage — treat tau as a tuned, versioned product parameter and publish NIL-rate as a headline health metric, not a hidden default.
- Do not over-link: aboutness is what the video is substantively about (a handful of salient concepts), not every noun mentioned — without salience/relevance filtering, subject precision collapses.
- Keep claims/takeaways out of the linking pipeline: a thesis is a proposition scored by faithfulness (entailment), and only its argument-slot concepts ground to the subject layer — conflating the two double-counts errors and corrupts both metrics.

## Claims / takeaways (propositions)

*confidence: high*

### Verdict
Model a saved video's advice/thesis as a first-class **Claim = a normalized proposition**, not an entity: it carries no durable authority ID and is never "linked" for correctness. Its identity is internal/emergent; its *arguments* (what it is about) reuse the already-grounded concept/entity nodes, so the moat's grounding flows in through `about[]` while the claim text stays free. Evaluate it by **faithfulness-to-source (grounded support), not truth and not ID-equality**: decompose → verify each claim against the video's own transcript/OCR/caption with an NLI/atomic-support checker (MiniCheck-FT5 / AlignScore, FActScore-style precision), and validate that automatic judge against a human gold set with Cohen's κ. For v1, ship ONE primary "Takeaway" Claim per video with a published, human-validated faithfulness rate + honest NIL (no crisp thesis → no claim). Define the full Claim schema now but populate only the primary slice; grow to multi-claim, comparative/stance, and cross-video Key-Point Analysis (canonical claims + prevalence + contradiction surfacing) in v2. This yields a SECOND publishable moat metric (faithfulness %) that is distinct from and additive to the entity-grounding accuracy metric — two moats, two metrics, never conflated.

### Model
TWO-TIER, occurrence-first, in the existing Post/Save/Referent (WEMI) split.

TIER 1 — ClaimOccurrence (per Post/Save; ships in v1). A Claim is *asserted by a Post*; it is NOT a Referent because it has no independent authority-backed existence — its truth lives in the world but its *assertion* lives in this video. Fields:
- `id` (internal only — NO external authority ID).
- `text` — normalized, decontextualized, stand-alone claim (the product of a claim-normalization step; e.g. "Cable lateral raises isolate the medial deltoid more effectively than dumbbell laterals"). This is what makes it retrievable and matchable.
- `evidence_span` + `evidence_modality` — the verbatim transcript/OCR/caption offsets the claim was extracted from, and which signal (spoken / on-screen text / caption / visual demo). REQUIRED — faithfulness eval is impossible without it.
- `about[]` — typed links {role ∈ subject|object|topic, target} to the SAME grounded nodes the entity + concept layers already produce (concept "medial deltoid"→QID/concept node; skill "lateral raise"; entity=a product). THIS is the composition point: ungrounded proposition, grounded arguments. Retrieval traverses `about[]` through the controlled vocabulary.
- `predicate` — a SMALL controlled relation vocab (recommends / causes / compares / defines / warns-against / equates / quantifies). Deliberately NOT open-IE arbitrary predicates (uncanonicalizable, no retrieval payoff). Gives a light subject–predicate–object skeleton without committing to RDF-triple extraction.
- `stance` / `comparative` — creator's stance (asserts / recommends / warns-against / debunks / prefers); for comparative advice a {better, worse, dimension} slot. Distinct from sentiment.
- `modality`/`strength` — hedged vs absolute ("can help" vs "fixes"), universal vs conditional ("if X, do Y"). Cheap, high value for honest retrieval.
- `claim_type` — empirical/factual vs normative-advice vs definitional vs experiential/anecdotal. This SELECTS the eval regime and the UI framing; it is NOT a truth judgment (adjudicating real-world truth is out of scope and a liability — the product certifies only "the video said this").
- `salience`/`is_thesis` — check-worthiness-style score; exactly one primary thesis per video + optional secondaries.
- `confidence` (extractor's) — kept SEPARATE from faithfulness (verified support). Honest NIL: pure vibe/aesthetic/entertainment clip with no crisp thesis → emit no Claim rather than hallucinate one (the propositional analog of NIL grounding).

TIER 2 — ClaimKeyPoint / canonical claim (corpus-level; EMERGENT, v2). When Key-Point-Analysis-style matching finds the same normalized proposition across many saved videos, promote it to a canonical KeyPoint node with a prevalence count. It is the propositional analog of a Referent BUT grounds to NOTHING external — its identity is established by claim-matching, not an authority ID. This powers "what do my saved videos agree/disagree on about creatine?" — the killer library feature and the natural home for contradiction surfacing.

FRAMING CHOICE (grounded, defended): a hybrid, not one paradigm. (a) Representation borrows CLAIM NORMALIZATION (noisy post → concise stand-alone claim) + ARGUMENT MINING's claim/premise + stance vocabulary — but NOT the full Toulmin warrant/backing graph or Relation-Identification support/attack tree (overkill and low-accuracy on 29s noisy multimodal clips). (b) CHECK-WORTHINESS (ClaimBuster / CheckThat! Task 1) is used only as a SALIENCE/priority signal to pick the thesis, not as representation. (c) KEY POINT ANALYSIS (IBM Project Debater) is the corpus-level canonicalization + claim-MATCHING engine — and, crucially, that matcher is also the "equality operator" the eval needs. (d) Aspect-Based Sentiment is a narrow specialization for the review-like subset only. (e) A single abstractive "takeaway" + faithfulness is the v1 baseline unit.

### Grounding & eval
GROUNDS TO: nothing. The Claim TEXT links to no authority and contributes ZERO to the entity-grounding ID-linking metric. Its `about[]` ARGUMENTS reuse the existing authorities (concept→Wikidata QID / concept node, entity→MBID/Place ID/QID). So the claim layer is evaluated by faithfulness + classification, never by ID-equality — this is the sharp line the task asks for.

EVAL — three distinct, separately-measured axes:

(1) FAITHFULNESS / grounded-support = PRIMARY, publishable moat metric. Question: is the extracted claim actually supported by the video's OWN content (transcript+OCR+caption, visual where available)? This is document-grounded fact-checking / summarization faithfulness with the claim as hypothesis and the multimodal transcript as premise. Metric: per-claim label ∈ {supported, partially-supported, unsupported/hallucinated}; aggregate = FActScore-style **faithfulness precision = #supported / #extracted** (arxiv 2305.14251). Compute at scale with an NLI/entailment support checker — MiniCheck-FT5 (770M, ~GPT-4 accuracy at ≈400× lower cost, purpose-built for "is this claim grounded in this document"; arxiv 2404.10774) or AlignScore/SummaC; add a QA-generation cross-check (QAGS/QuestEval) as a robustness pair (eugeneyan.com/writing/abstractive). This is FAITHFULNESS, explicitly NOT TRUTH — the product does not adjudicate real-world correctness.

(2) EXTRACTION QUALITY / thesis recovery — because faithfulness alone is gameable (the safest faithful claim is a trivial one). Build a small human gold set of canonical takeaways/video; score extracted thesis vs reference with semantic claim-matching — METEOR/BERTScore (the CheckThat! 2025 claim-normalization metric; arxiv 2503.14828) or, better, an LLM-judge KPA-style "same key point?" match → report key-point precision/recall (coverage) + is_thesis accuracy/MRR.

(3) INTER-ANNOTATOR AGREEMENT on free-text claims — the genuinely hard part, made tractable by: (i) NORMALIZE first so annotators judge canonical claims not raw spans; (ii) convert free-text into BOUNDED decisions with a real label space — "supported? [y/n/partial]", "C1 ≡ C2 same key point? [y/n]", "is C the primary thesis? [y/n]" — which make Cohen's κ (2 raters) / Krippendorff's α (3+) computable; (iii) replace ID-equality with a validated claim-MATCHING function (KPA matcher / LLM-judge) as the equality operator; (iv) use LLM-as-judge at scale ONLY after showing judge-vs-human κ ≥ ~0.6 (acceptable) / ≥0.8 (strong) on held-out human labels, and PUBLISH that κ — it is what converts "we graded ourselves with an LLM" into a credible measured moat; (v) also report human–human κ as the honest ceiling (thresholds per futureagi.com/blog/llm-as-a-judge and aclanthology 2408.09235).

V1 vs LATER (defended): SHIP v1 = one primary Takeaway Claim/video + faithfulness precision (MiniCheck/LLM-judge, human-validated κ) + NIL + `about[]` links; carry the full schema but populate only the primary slice. DEFER full multi-claim, comparative/stance ranking, and corpus KPA to v1.5/v2 — additive, not a migration. Rationale: the one claim-side number you can publish cheaply and credibly on day one is takeaway faithfulness; full argument-mining relation graphs / open-IE triples have poor cost/accuracy on short noisy clips and their agreement collapses.

### Evidence
- Claim normalization — turning a noisy social-media post into a concise, decontextualized, verifiable stand-alone claim — is an established task (CheckThat! 2025 Task 2, 20 languages) evaluated by METEOR against reference normalized claims; one approach recasts it as extractive summarization + QA-based decontextualization. This is the exact 'messy 29s transcript → clean Claim.text' step and its extraction-quality metric. — *https://arxiv.org/abs/2503.14828 ; https://checkthat.gitlab.io/clef2025/task2/*
- FActScore decomposes long text into atomic facts and scores factual precision = (#supported atomic facts)/(#extracted), verifying each against a source rather than issuing document-level binary judgments — the template for per-claim faithfulness precision and for the 'decompose then verify' pipeline. — *https://arxiv.org/abs/2305.14251*
- MiniCheck-FT5 (770M params) reaches GPT-4 accuracy for grounded sentence-level fact-checking at ~400x lower cost, purpose-built to decide whether a claim can be grounded in a document — the cheap production faithfulness gate (premise=video transcript, hypothesis=Claim.text). — *https://arxiv.org/abs/2404.10774*
- Faithfulness evaluation splits into two validated families: NLI/entailment-based (FactCC, SummaC, AlignScore) and QA-based (FEQA, QAGS, QuestEval); running an NLI checker as the workhorse plus a QA-generation cross-check is standard practice. — *https://eugeneyan.com/writing/abstractive/ ; https://www.sciencedirect.com/science/article/pii/S0957417424013228*
- IBM Project Debater Key Point Analysis takes many short opinionated texts and produces a succinct, non-redundant list of prominent key points with their prevalence, via key-point matching — the corpus-level canonicalization/claim-matching engine and the 'equality operator' that replaces ID-equality, plus the cross-video prevalence/agreement feature. 6M+ comments analyzed in production. — *https://research.ibm.com/blog/kpa-for-opinion-text ; https://arxiv.org/pdf/2110.10577*
- Check-worthy claim detection (ClaimBuster, CheckThat! Task 1) is a classifier/ranker for which sentences are worth fact-checking — best used as a salience/thesis-priority signal, not as the claim representation. — *https://arxiv.org/abs/2503.14828 ; https://www.researchgate.net/publication/379201170*
- LLM-as-a-judge is production-acceptable only when calibrated to humans: judge-to-human Cohen's κ ≥ 0.6 acceptable / ≥ 0.8 strong (Krippendorff's α for 3+ raters); published κ against a human gold set is what makes an automatic faithfulness number credible. — *https://futureagi.com/blog/llm-as-a-judge/ ; https://aclanthology.org/2025.winlp-main.37.pdf*
- Argument mining models a claim with premises and stance (modified Toulmin: claim/premise/backing/rebuttal) plus support/attack Relation Identification — a useful vocabulary for claim/premise/stance, but the full relation-graph apparatus is built for argumentative discourse and is overkill/low-yield for 29s advice clips. — *https://aclanthology.org/J17-1004.pdf*

### Pitfalls
- Conflating faithfulness with truth. Faithfulness certifies 'the video asserted this'; it says nothing about whether the advice is correct. Adjudicating real-world truth is out of scope, unscalable, and a liability — publish faithfulness %, never a truth score, and label claim_type so normative advice is never presented as verified fact.
- Faithfulness is gameable by triviality. A checker will pass 'this video is about fitness' as supported-but-useless. You MUST pair faithfulness (support vs source) with extraction-quality/thesis-recovery (coverage vs human reference); reporting only faithfulness invites optimizing for safe, empty claims.
- Grading yourself with an ungrounded LLM judge. Publishing an LLM-judge faithfulness rate without a human-validated κ is not a moat — it's circular. Budget for a human gold set (a few hundred (video, claim) pairs) and report judge–human AND human–human κ.
- Open-IE / arbitrary-predicate triples. Extracting free-form (subject, predicate, object) triples produces uncanonicalizable predicates, wrecks retrieval, and inflates the eval space. Keep predicate a small controlled vocab; a claim is one normalized proposition, not a triple store.
- Over-building v1: full Toulmin/argument-relation graphs, multi-claim relation extraction, and open argument trees have poor cost/accuracy on short noisy multimodal clips and their inter-annotator agreement collapses. Resist; ship one faithful primary Takeaway first.
- Missing evidence_span. If the extractor doesn't store the exact transcript/OCR offsets a claim came from, faithfulness is unverifiable and NIL is impossible to audit. Make evidence_span + evidence_modality mandatory outputs.
- No honest NIL for propositions. Forcing a thesis onto aesthetic/entertainment/vibe clips manufactures hallucinated claims and tanks faithfulness. Emit zero claims when there is no crisp proposition — the propositional analog of NIL grounding.
- Boundary/granularity disagreement in annotation. 'What is the claim' has no fixed label space, so naive exact-match agreement is ~0. Never ask annotators to free-write the claim for scoring; give them bounded decisions (supported? same-key-point? is-thesis?) over normalized claims so κ is computable.
- Treating the Claim as a Referent and minting a durable ID. A proposition has no authority-backed durable identity; corpus-level canonical claims are emergent via matching, grounded to nothing external. Don't force claims into the entity ID-linking machinery or its accuracy metric.

## Skills / occupations / services / actionable

*confidence: high*

### Verdict
Split this layer into four distinct machinery types, because they do not share a truth condition. (1) OCCUPATIONS and (2) SKILLS/TECHNIQUES are concepts, not named entities: ground them to ESCO as the primary controlled vocabulary (CC BY 4.0, free for commercial use, multilingual, downloadable + API, already cross-walked to Wikidata via P4652/P4644 and to the US via O*NET-SOC/SOC). Grounding here is CONCEPT-to-SKOS-vocabulary linking (skos:exactMatch/closeMatch/NIL), evaluated as linking accuracy@1 + NIL precision/recall — NOT instance entity-linking. (3) SERVICES and JOBS are decided by a single test: a proper name with one real-world/legal identity → ENTITY (org/brand/Place ID); a kind-of-service or role-type → CONCEPT (ESCO occupation, or an industry code like NAICS/ISIC for service categories); a specific opening or a comparison → STRUCTURED content. Do not over-type generic mentions of "coaching" or "physiotherapy" into entities. (4) ACTIONABLE content — recipes, workouts, how-tos, rankings — is STRUCTURED EXTRACTION into schema.org shells (Recipe, ExercisePlan, HowTo, ItemList), evaluated by field-level P/R/F1 and step recall/order, with slot values (ingredients, exercises, tools, ranked items) pointing DOWN into the entity and concept layers. Orthogonal to all of it, assign a small closed-enum FACET layer (intent/format/genre/actionability) modeled on IAB 3.0's "orthogonal vectors" and evaluated as multi-label classification. Claims/theses/advice are a fifth thing: propositions that ground to NOTHING and are scored by faithfulness-to-source, not by any authority.

### Model
Add four node kinds on top of the existing Post/Save/Referent (WEMI) + faceted-SKOS core, reusing its type→authority→instance grounding discipline.

1) CONCEPT nodes (occupation, skill, technique, subject, service-category) live in the controlled-core concept scheme as SKOS Concepts — NOT as WEMI Works and NOT as named-entity Referents. They attach to a Save/Referent by an aboutness relation (dct:subject / skos:relatedMatch). Occupation and skill are two typed sub-schemes: occupation Concepts carry skos:exactMatch to an ESCO occupation URI + Wikidata QID (occupation items already hold P4652 ESCO-occ, P8283 ISCO-08, P106 semantics); skill Concepts carry skos:exactMatch to an ESCO skill URI (P4644) and/or a Lightcast Open Skill ID. This is the class-vs-instance discipline you already enforce with Wikidata: an occupation is a class ("user experience designer"), never an instance.

2) STRUCTURED-WORK Referents. Extend the Referent slot: alongside named-entity Referents (film→QID, song→MBID) add typed structured Referents = schema.org/Recipe, /ExercisePlan (workout), /HowTo (instructions), /ItemList (ranking/product list). In WEMI terms the Recipe/HowTo is the durable Work that the TikTok Post embodies; the Save points at it. Its slots are typed fillers that reference the other layers: recipeIngredient→food concept, HowTo/ExercisePlan step→technique/skill Concept, tool/supply and ItemList members→entity IDs (product/brand/Place). So structured content is a composite shell whose values are grounded by the entity/concept machinery — the shell itself is extracted, not linked.

3) CLAIM nodes (takeaway/advice/thesis: "cable lateral raises isolate the medial delt better"). Model as first-class reified propositions (nanopublication / Wikidata-statement style): a Claim attached to the Referent, with typed links to the Concepts/entities it mentions. A Claim grounds to no authority — its object of evaluation is fidelity to the source video, plus optionally a stance/hedge attribute. This is where most "ideas/theses" content that today falls through to a coarse domain facet becomes first-class.

4) FACET layer (Ranganathan energy/personality facets specialized for short-video): intent (learn/shop/inspire/entertain), format (tutorial/talking-head/haul/skit/listicle), genre/domain, and an actionability flag (actionable-procedure vs ambient). These are closed enums, modeled after IAB Content Taxonomy 3.0's split of topic "aboutness" from orthogonal content "vectors" (format/media-type), with IPTC Media Topics (SKOS, ~1,200) and YouTube's small closed category set as sizing references.

Routing procedure (decidable, ordered): (a) proper name + single real-world identity? → ENTITY, link to entity authority. (b) a kind/class/field/skill/occupation? → CONCEPT, link to ESCO/Lightcast/industry-code as SKOS, else NIL + open folksonomy tag. (c) a subject-predicate-object assertion/advice? → CLAIM, no grounding. (d) a repeatable procedure or ordered collection with typed slots? → STRUCTURED, extract schema.org shell, recurse slots through (a)-(c). (e) always, orthogonally: assign FACETS. Worked example "how to become a UX designer": the Post is a STRUCTURED HowTo; "UX designer" is an occupation CONCEPT→ESCO "user experience designer"+QID; "Figma" is an ENTITY (software QID); "a bootcamp is enough" is a CLAIM; facets = intent:career, format:advice, actionability:actionable. "Salary negotiation": CONCEPT→ESCO skill / Lightcast "Negotiation"; specific numbers-advice = CLAIM.

### Grounding & eval
WHAT GROUNDS (to an authority) vs WHAT IS SCORED OTHERWISE, each with its exact metric:

OCCUPATION concept → GROUNDS to ESCO occupation (primary; CC BY 4.0; ~3,000 occupations, ISCO-08-based, RDF/CSV/JSON-LD download + web+local API) → Wikidata QID hub (P4652) → O*NET-SOC / SOC as the US-facing crosswalk (O*NET DB is CC BY 4.0 with a free Web Services API; BLS ISCO-08↔SOC crosswalk; ESCO↔O*NET AI+human-validated crosswalk exists). EVAL = concept-linking accuracy@1 (fraction of occupation mentions mapped to the correct ESCO/Wikidata id) + NIL precision/recall (did we correctly abstain when no authority match), reported macro across types. This is normalization/linking against a closed KB, not span-level entity F1.

SKILL / TECHNIQUE concept → GROUNDS to ESCO skill (P4644; ~13,500 skill/knowledge concepts) and/or Lightcast Open Skills (34,000+ skills, machine-readable IDs, biweekly updates, free/open with attribution, API). EVAL = linking accuracy@1 + NIL P/R. Many "techniques" ("sourdough hydration") won't exist in a skills taxonomy → correct behavior is NIL + concept/folksonomy node, and NIL recall is the metric that keeps you honest.

SERVICE → decision, not one target: named offering of a specific org ("ClassPass") → ENTITY (org/brand/Place ID), EVAL = entity-linking accuracy + NIL; service CATEGORY ("tax preparation", "dog walking") → CONCEPT grounded to an industry code (NAICS/ISIC) or ESCO/Wikidata, EVAL = concept-linking accuracy + NIL.

JOB → occupation/role sense = the OCCUPATION concept path above; a specific posting = schema.org/JobPosting STRUCTURED object referencing org-entity + occupation-concept (rare in saved shorts).

CLAIM / thesis / advice → GROUNDS TO NOTHING. EVAL = faithfulness/factual-consistency to the source video (NLI-style entailment against transcript+visuals) + claim-level precision/recall vs. a human-annotated gold set. Veracity/fact-checking is explicitly out of scope; the metric is "did the extractor faithfully capture what the video asserted," not "is the assertion true."

STRUCTURED CONTENT → EXTRACTION, not linking. Recipe (schema.org/Recipe): field-level P/R/F1 over recipeIngredient / recipeInstructions / recipeYield / cook-prep time, ingredient-normalization accuracy, step recall + step-order correlation. Workout (schema.org/ExercisePlan: exerciseType, repetitions, workload, activityDuration, restPeriods): field P/R/F1 + exercise→technique-concept linking accuracy + numeric sets/reps accuracy. How-to (schema.org/HowTo: step, tool, supply, totalTime): step recall + ordering (Kendall τ) + tool/supply linking. Ranking/product-list (schema.org/ItemList): item recall, rank correlation (Spearman/Kendall τ), and item→entity linking accuracy.

FACET layer → closed enums (IAB 3.0 vectors / IPTC Media Topics / YouTube categories as prior art). EVAL = multi-label classification: per-label precision/recall/F1 and macro-F1, plus calibration; no grounding, no NIL.

Net: publish accuracy@1 + NIL P/R for the CONCEPT/ENTITY grounding (the moat metric), field-P/R/F1 + step-recall for STRUCTURED, faithfulness for CLAIMS, and macro-F1 for FACETS — four different numbers, never averaged into one.

### Pitfalls
- Do not score occupation/skill grounding with span-level entity-F1: it is CLOSED-vocabulary concept normalization, so the honest metric is accuracy@1 plus NIL precision/recall. Reporting a single blended number hides that most short-video concepts (techniques, folk ideas) correctly resolve to NIL.
- Do not force skills/techniques into instance-linking. A skill is a SKOS Concept (a class), not a named individual; use skos:exactMatch/closeMatch/NIL, and keep unmatched techniques as governed folksonomy tags rather than inventing fake authority IDs.
- Over-typing services/jobs is the main failure mode. 'Coaching', 'physiotherapy', 'tax prep' are concepts/categories, not entities — only a proper name with a single legal identity (a company's named offering) is an entity. Bake the ordered decision test in so the extractor abstains from entity-linking generic services.
- ESCO is EU/education-labour oriented and can miss US-specific or hyper-current role titles; O*NET is US-only. Treat ESCO as primary + Wikidata as hub + O*NET/SOC as crosswalk, and expect real NIL rates — don't hide them.
- O*NET's redistribution clause matters for a shipped product: the DB is CC BY 4.0, but if you expose grounding via your own API, verify your clients' rights and carry the required attribution string; same for ESCO's mandatory acknowledgment statement.
- Lightcast Open Skills is 'open/free with attribution' for the taxonomy, but the richer extraction API is a commercial product — confirm the exact license/quota before depending on it in production (medium-confidence item, not fully verified here).
- LinkedIn Skills Genome / Skills Graph is proprietary and not offered as an openly licensable grounding authority — do not design it into the grounding path; use ESCO/Lightcast instead (assertion from general knowledge, verify if considered).
- Claims must not be graded as if they were entities or facts-in-the-world. The metric is faithfulness to the source video (did we capture what was said), scored by NLI/entailment + human-gold claim P/R; conflating this with veracity/fact-checking is scope creep and will tank measured 'accuracy'.
- Structured extraction needs BOTH field accuracy and step recall+ORDER — a recipe/workout with correct ingredients but shuffled steps is wrong; use rank-correlation (Kendall τ) for ordered slots, and separately measure the slot→concept/entity linking so extraction errors don't get blamed on grounding.
- Keep the facet enums genuinely closed and small (short-video-tuned intent/format/actionability), evaluated as multi-label macro-F1. Borrow IAB 3.0's aboutness-vs-vector separation so format/actionability never contaminates the subject facet.

## Integration: node typology + per-layer scorecard + v1 cut

*confidence: high*

### Verdict
Do not extend instance-linking to cover concepts, claims, and skills — that is the exact error the brief warns against. Commit instead to a SMALL discriminated union of four Referent kinds — NamedEntity, Concept, Claim, StructuredContent — plus orthogonal Facets, where each kind is defined by its GROUNDING REGIME and the regime dictates the eval metric. There are exactly four regimes, each borrowed from a mature field: (1) instance-linking to a closed KB → entity-linking F1 + NIL (the existing moat); (2) subject-indexing to an OPEN SKOS vocabulary → hierarchical F1@k with True-Path partial credit (the Annif / library-science precedent) — this is where concepts, subjects, fields, skills, occupations and services ALL live, routed to different authorities under ONE node type; (3) faithfulness-grounding of a proposition to its source span → faithfulness + coverage (Claimify / FEVERFact), never world-truth in v1; (4) slot-filling to a schema.org type → field + document accuracy. This quadruples expressiveness while adding exactly ONE new governed vocabulary (the subject scheme): claims are ungoverned-but-measured, structured content is externally governed by schema.org, and skills/occupations adopt ESCO/O*NET wholesale via adapters. That ratio — 4x expressiveness for +1 governance unit — IS the anti-MPEG-7 argument. The scorecard is honest precisely because it refuses to average four incommensurable metrics into one number: it is a matrix, one row per layer, each with its own metric, n, CI, publish-gate and grounds-to authority, with NamedEntity-grounding named the flagship and the rest marked "in calibration" until powered. v1 ships NamedEntity + Concept + Facet + one faithfulness-scored takeaway + recipes-only structured extraction; full multi-claim graphs and occupations/services grow later WITHOUT new node types (they slot into Concept-with-authority and additional Claim nodes). That is how the ontology stays durable while the first benchmark stays shippable — and publishing all four regimes per-layer is a discipline no consumer competitor (Recall, Stasht et al.) does.

### Model
INTEGRATED NODE TYPOLOGY — four Referent kinds + orthogonal Facets, composed on the existing WEMI + SKOS foundation.

THE SPINE (unchanged): Post (Manifestation) / Save (Item) / Referent. What changes is that Referent becomes a DISCRIMINATED UNION, not just the entity-Work it is today.

1) NamedEntity (EXISTING — keep verbatim). The instance axis (Wikidata P31). Grounds to an external instance ID in a closed KB: place→Google Place ID, film/TV→TMDB/QID, music→MBID, book→OLID. WEMI role: a Work — durable, deduped across all Saves that depict it (50 saves → 1 Place). This is doc-04 §5.2 as built.

2) Concept (NEW — the gap-closer, and the single highest-leverage addition). The class/subject axis (Wikidata P279 / library subject indexing). This is where MOST short-video 'aboutness' lives: ideas/themes (ADHD, flow state, stoicism, closing loops), subjects/fields (nutrition, macroeconomics), skills/techniques, and — later — occupations and service-types. CRITICAL: it is ONE node type with a PLUGGABLE AUTHORITY (a vocabulary), generalizing doc-03's 'type→authority→ID' into 'type→authority→concept-URI':
   • general subjects → your own SKOS subject scheme (authored small, exactMatch/closeMatch out to Wikidata classes + IPTC Media Topics so you inherit an external spine instead of authoring 10k terms);
   • skills/techniques → ESCO skills / Wikidata;
   • occupations → ESCO/O*NET occupations (LATER);
   • service-types → the subject scheme, with the specific provider grounded separately as a NamedEntity.
   Do NOT make theme/subject/field/skill/occupation separate node types — that is the MPEG-7 explosion. They are all skos:Concepts at different levels of one tree (Ranganathan/dumb-down handles granularity; 'subject/field' is just a broader concept than 'theme'). WEMI role: Concept is NOT a WEMI level — it is the SUBJECT relation hanging off the Work/Expression (FRBR 'has-subject'). Relation to NamedEntity: a Concept is the class, a NamedEntity is the instance; a single Save typically carries BOTH (a Dune-review save = NamedEntity(Dune→TMDB) + Concepts(science-fiction, film-criticism)).

3) Claim (NEW, but minimal in v1). A PROPOSITION — takeaway / advice / thesis ('cable lateral raises isolate the medial delt better'). It does NOT ground to an external ID and MUST NOT be forced into linking. Its grounding target is INTERNAL: the source span (frame timestamp + transcript span) it is faithful to — i.e., grounded to the VIDEO, not the world. WEMI role: attaches to the Expression (this creator asserts it in this post); its subject/predicate arguments MAY reference Concepts and NamedEntities. Later it may carry an optional external stance-link to a fact-check source, but v1 explicitly does NOT adjudicate truth (that is fact-checking scope creep).

4) StructuredContent (NEW, scoped to the wedge). A schema.org-typed extraction — Recipe (ingredients/steps/times), HowTo (steps/tools), Product-with-specs. Grounds to a schema.org type and fills its fields (which may themselves contain NamedEntity products and a Concept 'dish'). WEMI role: an Expression-level structured realization, optionally pointing up to a Work-level named recipe/dish.

FACETS (EXISTING — orthogonal, NOT a referent kind). intent / domain / medium / mood / actionability / trend, as closed enumerations classifying the Post/Save. Doc-03 §4.2.

GOVERNANCE MATH (the durability claim): expressiveness goes from 1 layer (entities) to 4, but the governed surface grows by exactly ONE authored vocabulary (the subject scheme, and even that reuses doc-03's SKOS + warrant + never-delete machinery). Claim = 0 governance (free propositions, evaluated not governed). StructuredContent = 0 (schema.org is externally governed). Skills/occupations = 0 authoring (adopt ESCO/O*NET via adapters, doc-03 alt A5). This is the MPEG-7-avoidance proof: every new degree of freedom is paid for with a constraint (a closed authority or a faithfulness rubric), never with unpaid expressiveness.

### Grounding & eval
THE UNIFYING PRINCIPLE: four grounding regimes, four canonical metrics, ONE matrix scorecard. The scorecard's honesty is that it never collapses these into a scalar — the denominators, chance baselines, and even the meaning of 'correct' differ per regime, so a blended 'accuracy %' would be statistically meaningless AND dishonest.

PER-LAYER GROUNDS-TO + METRIC (the answer to 'right target, right metric, not forced into linking'):

• NamedEntity — grounds to an INSTANCE ID in a closed KB (Places/TMDB/MusicBrainz/OpenLibrary/Wikidata). Regime: closed-world entity-linking. Metric: end-to-end linking Precision/Recall/F1 + NIL accuracy + disambiguation accuracy (GERBIL/ELEVANT idioms, doc-04 axis 6). 'Correct' = exact right identity. NIL semantics = closed-world ('not in this KB'). FLAGSHIP.

• Concept — grounds to a CONCEPT URI in an OPEN vocabulary (own SKOS scheme + Wikidata/IPTC/ESCO mappings). Regime: open-world, multi-label, ranked subject indexing (NOT 1:1 linking). Metric: hierarchical/set-based F1@k (micro AND macro), R-precision@k, reported at k≈5 (Annif found ~5 subjects/doc near-optimal). Partial credit via True-Path: getting the parent right when you miss the leaf earns credit (a hierarchical-F1 that walks the ancestor chain). 'Correct' = degree of topical match, not identity. 'NIL' here ≠ entity NIL — it means 'no governed concept applies', and the overflow lands in the open-tag/folksonomy layer (doc-03 REQ-8), not an error.

• Claim — grounds to NOTHING external; the target is the SOURCE SPAN. Regime: faithfulness/fidelity. Metrics: (a) faithfulness = fraction of extracted claims entailed by the video (VidFactScore/Claimify); (b) coverage = fraction of the video's salient takeaways captured (Key-Point-Analysis coverage) — MANDATORY alongside faithfulness, else the layer degenerates to 'extract one safe claim'; (c) atomicity/decontextualization quality (FEVERFact axes). Explicitly NOT world-truth in v1.

• StructuredContent — grounds to a SCHEMA (schema.org fields). Regime: slot-filling. Metrics: Field Accuracy (proportion of individual fields correct) + Document Accuracy (proportion of items where EVERY field is correct) — the structured-extraction literature's standard pair.

• Facets — classify the Post. Regime: classification. Metric: per-facet macro-F1 + Cohen's kappa (doc-04 axis 5), computed per facet because facets are independently governed.

THE SCORECARD DESIGN (one coherent, honest artifact): a single table, columns = Layer | Node type | Grounds-to (authority / vocabulary / span / schema / enum) | Regime | Metric(s) | n (annotations) | 95% CI | Publish-gate | v1 status. Rules that make it honest: (1) NO row is a scalar average of others; the 'headline' is a VECTOR, with NamedEntity-grounding F1 named the flagship number and everything else explicitly labelled. (2) Each row inherits doc-04's power gate — a metric is withheld / marked 'in calibration' until its own n clears threshold (≥245 for a headline, ≥100 with CI shown for a sub-surface), so the concept and claim layers publish only once their annotation counts are powered. (3) EVERY layer that uses an LLM-judge (faithfulness and concept-indexing especially) MUST pass doc-04 ADR-5: κ/ICC validation against human labels + swap-debias BEFORE any number is published — raw judge agreement inflates 33–41 points. (4) Two distinct NIL columns are reported (closed-world entity-NIL vs open-world no-concept), never merged. This matrix IS the moat artifact: Recall/Stasht do all of layers 1–2 invisibly and publish nothing; the defensible claim is 'here is measured accuracy, per layer, per regime, with intervals.'

- Distilling a video's 'takeaways' is the Key Point Analysis task, whose scoring is coverage-of-matching-mentions — grounding the mandatory coverage metric that must pair with faithfulness so the Claim layer cannot game by extracting one safe claim. — *https://research.ibm.com/blog/kpa-for-opinion-text ; https://arxiv.org/pdf/2110.10577 (Overview of the 2021 Key Point Analysis Shared Task)*
- Structured extraction has its own standard metric pair — Field Accuracy (per-field correctness) and Document Accuracy (all-fields-correct) — and public structured-output benchmarks are error-riddled, reinforcing the need for a private version-locked golden set for the StructuredContent (recipe/HowTo) layer. — *https://arxiv.org/html/2510.08623v1 (PARSE: LLM-driven schema optimization); https://cleanlab.ai/blog/structured-output-benchmark/ (LLM Structured Output Benchmarks are Riddled with Mistakes)*
- Occupations and skills are grounded to ESCO/O*NET as closed taxonomies (ESCO v1.2.0 = 3,039 occupations, 13,939 skills), and occupation entity-linking has a dedicated benchmark (MELO) with linking metrics — confirming skills/occupations slot in as Concept-with-authority routed to different vocabularies, occupations behaving like closed-world linking (F1), and justifying deferral to 'later' behind an adapter. — *https://arxiv.org/pdf/2410.08319 (MELO: Multilingual Entity Linking of Occupations); https://arxiv.org/pdf/2401.17979 (Entity Linking in the Job Market Domain)*
- NIL prediction (mention not in the KB) is a first-class, underserved problem in entity linking, and its semantics are closed-world — distinct from the open-world 'no governed concept applies' overflow in subject indexing; the scorecard must keep the two NIL columns separate. — *https://dl.acm.org/doi/10.1145/3795134 (Entity Linking with Wikidata: A Systematic Literature Review); ACL 2023 'Learn to not link: Exploring NIL prediction in entity linking'*
- Current multimodal-RAG / video systems already represent aboutness in MULTIPLE layers — a graph of static+dynamic entities plus visual (scenes/objects/locations), temporal (actions/events) and verbal (transcript) descriptions, and scene graphs give structured subject-predicate-object beyond flat tags — evidence that a multi-layer semantic scheme (entities/concepts/actions/claims) is the state of practice, not an invention. — *https://arxiv.org/abs/2508.05318 (mKG-RAG); https://arxiv.org/html/2512.20136v1 (M3KG-RAG); https://arxiv.org/pdf/2506.21556 (VAT-KG); https://arxiv.org/pdf/2312.03050 (HIG video scene-graph)*
- Consumer 'second brain' tools (Recall, 500k+ users) already auto-extract ENTITIES and TOPICS/key CONCEPTS separately and auto-link them into a personal knowledge graph — validating the entity-vs-concept split at the consumer layer, but they publish NO accuracy, which is precisely the measured-per-layer moat gap. — *https://www.recall.it/ ; https://chromewebstore.google.com/detail/recall-your-knowledge-is/ldbooahljamnocpaahaidnmlgfklbben*

### Pitfalls
- The NIL trap (forcing concepts into instance-linking): treating 'stoicism' or 'flow state' as an entity to link to one Wikidata Q yields artificially low F1 and a flood of false NILs. Concepts are ranked multi-label subject assignment (F1@k with hierarchical partial credit), not 1:1 identity linking. This is the single error the brief names.
- Category error on claims: a takeaway ('cable laterals isolate the medial delt better') is a proposition, not a subject tag and not an entity; scoring it by linking F1 or by concept F1 is meaningless. Score faithfulness+coverage. And do NOT slide into adjudicating world-truth in v1 — that is fact-checking scope creep the golden set cannot support.
- The single blended number: averaging linking-F1, indexing-F1@k, faithfulness, and slot-accuracy into one 'accuracy %' is statistically incoherent (different denominators, chance baselines, and meanings of 'correct') and dishonest. Publish a matrix, one metric+n+CI per layer; the headline is a vector with NamedEntity-grounding named as flagship.
- MPEG-7 explosion via node-type proliferation: creating separate node types for theme/subject/field/skill/occupation/service multiplies governance and collapses inter-annotator agreement. They must all be Concept-with-a-pluggable-authority (or Facets). Adding authorities under one node type is cheap; adding node types is not.
- Concept-vocabulary governance debt: a home-grown subject scheme can bloat like a folksonomy or ossify like a closed vocab. Bind it to doc-03 warrant-based promotion + never-delete from day one, and exactMatch to Wikidata/IPTC so you inherit an external spine instead of authoring ~10k subjects by hand.
- Coverage blind spot: faithfulness alone rewards saying nothing (extract one safe claim). The Claim layer MUST pair faithfulness with a coverage metric (Key Point Analysis) or it degenerates — this is why v1's single-takeaway cut is honest only if labelled as fidelity-of-one-claim, not completeness.
- LLM-judge inflation on the NEW layers: the doc-04 κ/ICC-validation + swap-debias discipline must extend to the concept-indexing and (especially) claim-faithfulness judges before any number is published; raw judge agreement inflates 33–41 points and would silently corrupt exactly the two layers with the softest ground truth.
- Conflating the two NILs: closed-world entity-NIL ('not in this KB') and open-world concept-overflow ('no governed subject applies, goes to open tags') are different outcomes with different correctness semantics. Merging them in the scorecard hides where the system is actually failing.
